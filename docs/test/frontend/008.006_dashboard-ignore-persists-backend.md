# Test Case: 008.006_dashboard-ignore-persists-backend

## Test Objective

Regression for srat#1302: clicking IGNORE on a Dashboard problem card must persist to the backend (`PUT /api/problems/{key}` with `ignored:true`), not just hide locally. A reload must NOT resurrect the card, and the bell badge must drop.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; health 200
2. Protection mode ON with `protected_mode` problem active and NOT ignored: `GET /api/problems/protected_mode` → `ignored:false` (re-enable via `PUT` if needed)
3. Frontend at `http://localhost:3080/` → Dashboard tab shows the "Addon in Protected Mode" card with IGNORE button; record bell badge count (`BASE_BADGE`, expect ≥1)

**If any preparation step fails** (no active problem, card absent), **skip**.

## Execution

1. Click the card's IGNORE button (the one inside Actionable Items, not the toast's) → within 5 s capture Playwright network log filtered for `PUT /api/problems/*`
2. Assert a `PUT /api/problems/protected_mode` fired → 200
3. Assert backend state: `GET /api/problems/protected_mode` → `ignored:true`, `status:ignored`
4. Assert bell badge dropped (`< BASE_BADGE`) and toast entry gone without opening the bell

**Assertions:**

- Exactly one `PUT` to `/api/problems/protected_mode` per click (no-op clicks fail this test)
- Backend `ignored:true` within 5 s of the click
- Zero console errors during the flow

## Validation

1. Reload `http://localhost:3080/` → Dashboard card stays hidden (proves persistence, not local state)
2. Re-enable via API (`PUT` with `ignored:false, status:created`) → card returns, badge restores (cleanup + proves round-trip)
3. Check addon logs: no `ERROR`/`panic` correlating with the ignore

**Success criteria:** IGNORE persists server-side on first click; reload keeps it hidden; re-enable restores; no log errors.
