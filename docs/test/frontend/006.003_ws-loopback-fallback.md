# Test Case: 006.003_ws-loopback-fallback

## Test Objective

Verify the SRAT custom component WebSocket client tries `127.0.0.1` first for Supervisor-managed add-ons, falling back to the gateway address when loopback is unreachable. This prevents 401 errors when HA Core and the addon both use host networking.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `state: started`
2. Health check: `curl -s http://192.168.0.68:3000/api/health` → 200
3. Custom component installed: `docker exec app_local_sambanas2 ls /homeassistant/custom_components/srat/manifest.json` → exists; if not, install via `POST /api/settings/homeassistant/custom-component/install`
4. HA config entry exists: `curl -s http://192.168.0.68:3000/api/settings/homeassistant/custom-component/status | jq .connected` → note `BASE_CONNECTED`
5. Frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/`

**If any preparation fails** (health not 200, component not installed), **skip**.

## Execution

1. **Enable debug logging:** Add to HA `configuration.yaml`:
   ```yaml
   logger:
     default: info
     logs:
       custom_components.srat: debug
       custom_components.srat.websocket_client: debug
   ```
   Reload HA core: `ha core restart` (or via MCP `mcp_home-assistan_ha_reload_config`)
2. **Trigger reconnect:** Restart the addon to force WS reconnection: `ha addons restart local_sambanas2`; wait ~15s
3. **Check connection order in logs:** `ha core logs | grep -i "Connecting to SRAT WebSocket"` → verify the first connection attempt is to `ws://127.0.0.1:<port>/ws`
4. **Verify successful connection:** `ha core logs | grep -i "Connected to SRAT WebSocket"` → should show successful connection (either via loopback or gateway fallback)
5. **Frontend WS indicator:** Navigate to `http://localhost:3080/` → NavBar WS indicator should be green (connected)

**Assertions:**

- First WS connection attempt targets `127.0.0.1`
- Connection succeeds (either loopback or gateway fallback)
- No `Unauthorized access from` errors in addon logs
- Frontend shows connected state

## Validation

1. **Loopback unreachable fallback:** Stop the addon, remove the loopback route (if possible), start addon → verify it falls back to `172.30.32.1` gateway and still connects
2. **Normal operation:** Restart addon → verify it connects via loopback first again
3. **Logs:** `ha core logs | grep -c "Unauthorized access from"` → 0 (no 401 errors)
4. **Restore logging:** Remove debug logger config from `configuration.yaml`, reload HA core

**Success criteria:** Loopback is tried first, fallback works, no 401 errors, frontend connected.
