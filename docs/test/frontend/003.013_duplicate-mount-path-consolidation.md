# Test Case: 003.013_duplicate-mount-path-consolidation

## Test Objective

Verify that the Volumes UI correctly consolidates duplicate or overlapping mount paths for the same partition, showing a single row with a combined view of mount points rather than multiple separate rows, and that the UI handles mount state changes without leaving stale or phantom rows.

## Preparation

1. Ensure the SRAT addon is running and the frontend dev server is reachable at `http://localhost:3080/`
2. Open the Volumes tab in the browser
3. Have a partition that may have multiple mount paths or could be in a transitional state (e.g., after a mount/unmount cycle)

**If any preparation step fails**, the test must be **skipped**.

## Execution

### Part A: Multiple Mount Paths Consolidation

1. Navigate to the Volumes tab and locate a partition that has **multiple mount points** in the UI (e.g., from the details panel or row indicators)
2. Verify that the partition appears as a single row (not duplicated)
3. Assert that:
   - The partition row shows a badge or indicator for multiple mount points
   - The mount points are listed together in a single details panel
   - No separate row exists for each mount path (unless they belong to different partitions)
   - Actions (Create Share / Go to Share / Unmount) are available for each mount entry
4. If the partition has both HA-managed and SRAT mounts, verify that the UI clearly distinguishes between them (badge, path format, etc.)

### Part B: Mount State Changes Without Stale Rows

1. Record the current partition rows in the Volumes tab (using the row list or tree view)
2. Trigger a mount state change for a partition:
   - Mount: click "Mount Partition" for a partition currently not mounted
   - Unmount: click "Unmount Partition" for a partition currently mounted
3. Wait for the state change to propagate (≤10s for polling, or immediate for udev events)
4. Re-check the partition rows
5. Assert that:
   - The partition row updates to reflect the new mount state
   - No stale or phantom rows remain (e.g., no duplicate rows with old mount paths)
   - The UI correctly shows the new mount points and any associated actions
   - If the partition had a share before unmount, the UI correctly handles the transition (e.g., disables actions appropriately)

### Part C: Multiple Mount Paths Edge Case (HA + SRAT)

1. Locate a partition with both an HA-managed mount (`is_ha_mounted: true`) and an SRAT mount (e.g., `/mnt/usbtest`)
2. Verify the UI shows a single row for the partition with both mount points listed
3. Assert that:
   - The "Managed by Home Assistant" badge is shown for the partition (if any mount is HA-managed)
   - Actions for the HA mount entry are limited (Create Share / Go to Share)
   - Actions for the SRAT mount entry include full lifecycle (Mount / Unmount / Automount / etc.)
   - No confusion in action availability (e.g., "Unmount" only shows for the SRAT mount entry, not the HA mount entry)

**Assertions:**

- Single row per partition even with multiple mount paths
- Mount points are consolidated in the details panel or row indicators
- No stale or phantom rows remain after mount state changes
- HA and SRAT mount entries are visually and functionally distinct
- Actions are correctly available based on mount state and ownership

**Success criteria:** Duplicate or overlapping mount paths are consolidated in the UI; mount state changes are reflected without stale rows; HA and SRAT mounts are correctly distinguished with appropriate actions.
