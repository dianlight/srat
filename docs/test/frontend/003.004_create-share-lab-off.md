# Test Case: 003.004_create-share-lab-off

## Test Objective

Verify CREATE SHARE on a mounted data partition with lab OFF (prefers WD part2). Short test, cleanup deletes share. Lab OFF must not block Volumes → Shares flow.

## Preparation

1. Same as 003.002: addon `c1bed217`, lab OFF, frontend `API_URL=http://192.168.0.68:3000/` at `http://localhost:3080/` with VOLUMES present, `smb.conf` absent (see 003.002 steps 1-3).
2. Use `TEST_PARTITION_ID` / `TEST_MOUNT_PATH` from 003.002 step 4 (generalized). If not set, determine as in 003.002: prefer WD part2, otherwise ask user which partition to use (mounted, `is_write_supported:true`, not system). Ensure `is_mounted:true` (remounted after 003.003). If `false`, mount via `POST /api/volume/mount`.
3. Share must not exist: `curl -s http://192.168.0.68:3000/api/shares | jq -r '.[].name'` → no `wdtest*` for this run. If exists, `DELETE /api/share/<name>` first.
4. Generate name: `TEST_SHARE="wdtest$(date +%s | tail -c 5)"` (or `test$(date +%s)` for non-WD; sanitize via `toKebabCase`, ≤12 chars base).

**If preparation fails**, skip.

## Execution

1. VOLUMES → select `$TEST_PARTITION_ID` → Actions `CREATE SHARE` (MUI `colorSuccess`) visible even with lab OFF? Verify source `PartitionActions.tsx` `create-share` not gated by lab (unlike `smb.conf` tab).
2. Click `CREATE SHARE` → navigates to Shares tab with `newShareData` (or dialog `ShareEditForm`). Fill: `name=$TEST_SHARE`, `mount_point_data.path=$TEST_MOUNT_PATH` (plus `device_id` from volume), `description="Test lab OFF"`, `guest_ok:true`, `usage:media`. Submit `type="submit"` → toast success. *Alternative API path (if UI nav flaky):* `mnt=$(curl -s /api/volumes | jq --arg pid "$TEST_PARTITION_ID" '.[] | select(.partitions[$pid]!=null) | .partitions[$pid].mount_point_data | to_entries[0].value')` then `jq -n --arg name "$TEST_SHARE" --argjson mnt "$mnt" '{name:$name, mount_point_data:$mnt, usage:"media", guest_ok:true, timemachine:false}' | POST /api/share` → 200.
3. Verify API: `curl -s http://192.168.0.68:3000/api/shares | jq --arg n "$TEST_SHARE" '.[] | select(.name==$n)'` → exists with `mount_point_data.path==$TEST_MOUNT_PATH`. Also `docker exec app_local_sambanas2 testparm -s | grep -A3 $TEST_SHARE` → share block present.
4. Verify UI: Shares tab list shows `$TEST_SHARE`, Volumes detail for `$TEST_PARTITION_ID` now shows `GO TO SHARE` instead of `CREATE SHARE`.
5. Verify `smbclient -L //192.168.0.68 -U guest%` or `smbclient //192.168.0.68/$TEST_SHARE -c "ls"` → share connectable (if guest allowed).

## Validation

1. Cleanup delete: `curl -X DELETE http://192.168.0.68:3000/api/share/$TEST_SHARE` → 200/204. Verify `GET /api/shares` no longer contains it, `testparm` no share block, Volumes Actions back to `CREATE SHARE` (needs re-select of `$TEST_PARTITION_ID`).
2. Logs: `docker logs app_local_sambanas2 | tail -n 20` → no `ERROR` for share create/delete.
3. WS: `shares` event emitted within 5s, payload without deleted share.
4. Leave lab OFF.

**Success criteria:** CREATE SHARE works with lab OFF on mounted WD part2 and is cleanly deleted.
