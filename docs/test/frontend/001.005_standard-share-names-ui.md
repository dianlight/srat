# Test Case: 001.005_standard-share-names-ui

## Test Objective

Verify the Shares tab tree honors Settings `standard_share_names` mode via the `status.is_hidden` annotation (#1145 fixes #1142): `old` shows only `addons`/`addon_configs`, `new` shows only `local_apps`/`app_configs`, `both` shows all four. Legacy badge (`shares-legacy-badge`) stays on legacy rows only.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Backend prerequisite: #1145 deployed — `PUT /api/settings` with `standard_share_names:old` → `GET /api/shares` shows `status.is_hidden:true` on `local_apps`/`app_configs`. If no `is_hidden` annotation is present, **skip** (fix not deployed)
3. Save ORIG settings JSON for cleanup; ensure all four standard shares are enabled (`PUT /api/share/<name>/enable` for any with `disabled:true`) so the disabled flag does not confound the matrix — restore flags after
4. Frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/`; WS indicator green; no console errors after load

**If any preparation step fails** (backend still unfiltered, UI unreachable), **skip** and document.

## Execution

1. **Mode `old`:** `PUT /api/settings` with `standard_share_names:old` → 200; reload Shares tab → expand `Internal Shares` group → rows `addons` and `addon_configs` present, each with `getByTestId("shares-legacy-badge")`; rows `local_apps`/`app_configs` absent
2. **Mode `new`:** `PUT /api/settings` with `standard_share_names:new` → 200; reload → rows `local_apps` and `app_configs` present, no legacy badge on them; rows `addons`/`addon_configs` absent
3. **Mode `both`:** `PUT /api/settings` with `standard_share_names:both` → 200; reload → all four rows present; legacy badge only on `addons`/`addon_configs`

**Execution note:** the MUI tree-view index renumbers on reload (`mui-tree-view-2` → `mui-tree-view-1`) — never reuse element selectors across a reload; take a fresh snapshot and re-resolve the group/item selectors each pass. Group-count badges (`Internal Shares (7/7/9)`) are a cheap first assertion before expanding rows; capture a screenshot per mode as evidence.

**Assertions:**

- Visible rows match mode exactly (2/0/4 standard rows for old/new/both)
- Legacy badge present only on legacy rows when visible
- No console errors, `GET /api/shares` 200 each reload, WS stays green

## Validation

1. Cleanup: `PUT /api/settings` with ORIG JSON → 200; restore any `disabled` flags changed in preparation; verify tree back to baseline
2. Check logs: addon logs no `ERROR`/`panic` from shares rendering
3. Record screenshots per mode + share-row lists as evidence

**Success criteria:** Tree rows follow mode in all three cases, badge gating correct, settings restored, no log errors.
