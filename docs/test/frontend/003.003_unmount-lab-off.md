# Test Case: 003.003_unmount-lab-off

## Test Objective

Verify UNMOUNT PARTITION for a mounted data partition with lab OFF (prefers WD part2). Short test, cleanup remounts.

## Preparation

1. Same as 003.002: addon `c1bed217`, lab OFF, frontend `API_URL=http://192.168.0.68:3000/` at `http://localhost:3080/` with VOLUMES present.
2. Use `TEST_PARTITION_ID` / `TEST_MOUNT_PATH` from 003.002 step 4 (generalized). If not set, determine as in 003.002 step 4: prefer WD part2, otherwise ask user which partition to use (mounted ext4, `is_write_supported:true`, not system). Export vars.
3. Verify chosen partition `is_mounted:true` (re-enabled after 003.002). `curl -s http://192.168.0.68:3000/api/volumes | jq --arg pid "$TEST_PARTITION_ID" '.[] | select(.partitions[$pid]!=null) | .partitions[$pid] | {mounted: (.mount_point_data|to_entries[0].value.is_mounted == true)}'` → `true`. If `false`, mount via `POST /api/volume/mount` with that `mount_point_data` or UI MOUNT dialog. Also ensure `is_to_mount_at_startup:false` before unmount (set via 003.002 DISABLE) so it stays unmounted; if `true`, DISABLE first.
   Note: use `is_mounted == true` (NOT `mount_point_data|length>0`)—the map is the persisted mount config and survives unmount. Caveat: `is_mounted` is omitted from JSON when `false` (`omitempty`, see #1009), so `== true` yields `false` for both unmounted and absent.
4. Ensure no existing share blocks unmount (`share==null` for that partition; `curl -s /api/volumes | jq --arg pid "$TEST_PARTITION_ID" '.[] | select(.partitions[$pid]!=null) | .partitions[$pid].mount_point_data | to_entries[0].value.share // empty'`). If share exists, `DELETE /api/share/<name>` first.
5. `dmesg | tail -1` baseline before test (check for rescan spam).

**If preparation fails**, skip.

## Execution

1. VOLUMES → select `$TEST_PARTITION_ID` (expand its disk) → detail Actions shows `UNMOUNT PARTITION` and `FORCE UNMOUNT PARTITION` (both enabled, not gated by lab OFF).
2. Click `UNMOUNT PARTITION` → confirm dialog `Unmount this volume?` → `UNMOUNT` (if `Mui-disabled`, the partition still has `is_to_mount:true`—DISABLE first). UI updates to `Status: Not Mounted`.
3. Verify API: `curl -s http://192.168.0.68:3000/api/volumes | jq --arg pid "$TEST_PARTITION_ID" '.[] | select(.partitions[$pid]!=null) | .partitions[$pid] | {mounted: (.mount_point_data|to_entries[0].value.is_mounted == true)}'` → `false` (field absent when false—#1009). Also `lsblk` on host shows `MOUNTPOINT=""` for that device.
4. Verify WS `volumes` event: `is_mounted:false` for that partition within 2 seconds (see #971).
5. Snapshot after unmount (Actions should now show `MOUNT PARTITION` / `ENABLE AUTOMATIC MOUNT`).

**Assertions:**

- UNMOUNT clickable with lab OFF
- API and WS show unmounted
- No `ERROR` in `docker logs app_local_sambanas2` for unmount

## Validation

1. Cleanup remount: click `MOUNT` (or `POST /api/volume/mount` with `mountPointData` from `TEST_MOUNT_PATH`) → API `mounted:true` again. If `is_to_mount_at_startup` was `false` before, PATCH it back to `true` via `PATCH /api/volume/settings` (see 003.002 cleanup). WS shows remounted.
2. `dmesg` diff vs baseline → no SCSI storm.

**Success criteria:** UNMOUNT toggles mounted false→true with lab OFF, cleanup restores mounted state.
