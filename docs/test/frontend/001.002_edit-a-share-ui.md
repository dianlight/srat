# Test Case: 001.002_edit-a-share-ui

## Test Objective

Verify that the frontend UI allows users to edit an existing SMB share's properties and that changes are persisted correctly.

## Preparation

1. Ensure the SRAT addon is running: `addon ls` - should show srat addon as `running`
2. Start Home Assistant frontend: ensure the UI is accessible at `http://localhost:8123`
3. Navigate to the Share Management page: `http://localhost:8123/srat/shares`
4. Verify at least one share exists in the list (create one via API if needed)
5. Record the share name to edit: `EDIT_SHARE=$(curl -s http://localhost:8090/api/shares | jq -r '.[0].name')`
6. Open the share edit dialog for the recorded share
7. Verify the edit form is populated with current share values

**If any preparation step fails** (no shares exist, UI not accessible, edit form not loaded), the test must be **skipped**.

## Execution

1. Modify the share properties in the edit form:
   - Change Description to "Updated via test case 001.002"
   - (Optional) Change Path or subdirectory if fields are available
2. Select the "Update Share" or "Save" button
3. Wait for the UI to show a success notification or toast message
4. Verify the share list updates to reflect the changes

**Assertions:**
- Success notification/toast appears after share update
- Share list reflects the modified description
- Other share properties remain unchanged unless explicitly modified

## Validation

1. Verify the updated share via the SRAT API:
   ```bash
   curl -s http://localhost:8090/api/shares | jq "select(.name == \"${EDIT_SHARE}\")"
   ```
2. Confirm the description field shows "Updated via test case 001.002"
3. Check that other share properties remain unchanged
4. Test that the share can still be deleted via the frontend UI
5. Test that the share can still be viewed via the frontend UI

**Success criteria:** Share updated via UI is verifiable through API, and the share remains functional with edit/delete capabilities.
