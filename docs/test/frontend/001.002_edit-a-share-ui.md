# Test Case: 001.002_edit-a-share-ui

## Test Objective

Verify that the frontend UI allows users to edit an existing SMB share's properties and that changes are persisted correctly.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Ensure frontend is served at `http://localhost:3080/` (via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote`)—page loads with no JS errors
3. Navigate to Shares: `http://localhost:3080/` → click Shares tab (`#full-width-tab-2`) → expand group containing the target share
4. Verify at least one share exists in the list (create one via `001.001` preparation if needed)
5. Record the share name to edit: `EDIT_SHARE=$(curl -s http://192.168.0.68:3000/api/shares | jq -r '.[0].name')`
6. Open the share edit dialog for the recorded share (`SharesTreeView` → `ShareActions` → Edit) and verify the form is populated with current values

**If any preparation step fails** (no shares exist, UI not accessible, edit form not loaded), the test must be **skipped**.

## Execution

1. Modify the share properties in the edit form:
   - Change Description/usage fields as exposed by `ShareEditForm` (e.g. `usage` or `guest_ok` if shown)
   - Keep `mount_point_data.path` unchanged unless the test explicitly covers path migration
2. Select the "Update Share" or "Save" button
3. Wait for the UI to show a success notification or toast message
4. Verify `SharesTreeView` and `ShareDetailsPanel` update to reflect the changes without reload

**Assertions:**

- Success notification/toast appears after share update
- Share list/detail reflects the modified fields
- Network `PUT /api/share/${EDIT_SHARE}` returns 200 and `GET /api/shares` reflects the change
- Other share properties remain unchanged unless explicitly modified

## Validation

1. Verify the updated share via the SRAT API:
   ```bash
   curl -s http://192.168.0.68:3000/api/shares | jq --arg n "$EDIT_SHARE" '.[] | select(.name==$n)'
   ```
2. Confirm `testparm -s` still contains the share block after soft restart: `ssh root@192.168.0.68 "docker exec app_local_sambanas2 testparm -s 2>&1 | grep -i \"\[$EDIT_SHARE\]\""`
3. Check WS `shares` event: `ws://192.168.0.68:3000/ws` stream contains updated `event: shares` within 5 seconds
4. Verify share remains functional: can still be viewed and deleted via UI

**Success criteria:** Share updated via UI is verifiable through API, `smb.conf`, and WS, and the share remains functional with edit/delete capabilities.
