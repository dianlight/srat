# Test Case: 007.006_custom-component-lab-gating-ui

## Test Objective

Verify the dashboard never notifies for the SRAT custom component while the `ha_custom_component` lab feature is inactive: no problem toasts (`App.tsx`), no `IssueCard` entries under Actionable Items, and no custom-component section in Settings → HomeAssistant; with the feature active (dev/prerelease + lab on) the missing-component card appears and resolves through the normal flow.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Backend gate verified first: run `docs/test/backend/007.003_custom-component-lab-gating.md` steps 1–3 → endpoints 403, problems clean; if not, **skip** (UI cannot pass on a leaking backend)
3. Frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/` → page loads, WS indicator green, `bun tsc --noEmit` green, no console errors
4. Confirm feature state: `curl -s http://192.168.0.68:3000/api/lab_features` → `ha_custom_component` absent (production) or `available:false` (lab off)

**If any preparation fails** (backend leaks, frontend fails `tsc`, WS red), **skip**.

## Execution

1. Navigate `http://localhost:3080/` → Dashboard → expand `Actionable Items` → assert no card titled `Home Assistant SRAT custom component missing and disconnected`; assert no toast with that title appears within 10 s of load
2. Navigate Settings → HomeAssistant → assert the `SRAT custom component` install/upgrade panel is absent; assert no `custom component status` network call leaves pending (the query is skipped: expect none, or a single 403 at most)
3. Lab-on path (dev/prerelease builds only; skip on production): enable lab mode (`PUT /api/settings` full body with `experimental_lab_mode:true`), reload UI → Actionable Items shows the missing-component card; reload again after `DELETE /api/problems/custom_component_missing` → card gone, toast dismissed
4. Restore lab mode: `PUT /api/settings` with baseline body → reload UI → card and toasts stay absent

**Assertions:**

- Feature inactive: no toast, no card, no settings panel for the custom component
- Feature active (non-production): card appears on raise, disappears on dismiss, no console errors

## Validation

1. Cleanup: settings restored to baseline (`GET /api/settings | jq .experimental_lab_mode` matches); problems contain no test-created keys
2. Check console via `browser_console_messages` → no uncaught errors; `browser_network_requests` → no failing `custom-component` calls except the expected gated 403s
3. Record evidence: screenshots of Actionable Items (inactive + active), toast absence note, network log excerpt

**Success criteria:** UI surfaces exactly track `ha_custom_component` availability with settings restored to baseline.
