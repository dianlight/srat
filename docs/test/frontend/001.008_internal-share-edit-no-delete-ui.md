# Test Case: 001.008_internal-share-edit-no-delete-ui

## Test Objective

Verify that the Share Configuration panel in edit mode does NOT render the Delete button for internal shares (`usage === "internal"`), while non-internal shares still show Delete alongside Apply. Covers both the embedded card form (`ShareEditForm`, `showActions`) and the edit dialog (`ShareEditDialog`).

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. At least one internal share exists: `curl -s http://192.168.0.68:3000/api/shares | jq -r '.[] | select(.usage=="internal") | .name'` → non-empty (e.g. `config`); if empty, **skip**
3. At least one non-internal share exists (create a test share first if needed); if none can be provided, run only the internal-share half and document
4. Frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/`; WS indicator green; no console errors after load

**If any preparation step fails** (no internal shares, UI unreachable), **skip** and document.

## Execution

1. **Internal share:** Shares tab → expand `Internal Shares` group → select an internal share (e.g. `config`) → Share Configuration panel shows edit form → assert NO Delete button is rendered (only Apply); capture a screenshot as evidence
2. **Non-internal share:** select a non-internal share (e.g. a media/backup test share) → assert BOTH Delete and Apply buttons are rendered; do NOT click Delete; capture a screenshot as evidence

**Assertions:**

- Internal share edit form: Delete button absent, Apply present
- Non-internal share edit form: Delete and Apply both present
- No console errors, `GET /api/shares` 200, WS stays green

## Validation

1. No state mutated (no share created/modified/deleted during this case) — nothing to clean up
2. Check logs: addon logs no `ERROR`/`panic` from shares rendering
3. Record both screenshots + share `usage` values from `GET /api/shares` as evidence

**Success criteria:** Delete hidden for internal shares, visible for regular shares, no log errors.
