# Test Case: 008.003_protected-mode-ignore-flow

## Test Objective

Verify the permanent-ignore flow for the `protected_mode` alert (dianlight/hassio-addons#730): with protection mode ON the dashboard shows the backend-driven "Addon in Protected Mode" issue card with an Ignore button; clicking Ignore hides the card everywhere (dashboard + Home Assistant repairs/persistent notifications) and the ignore survives an addon restart; Re-enable restores the card while protection is still ON.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Record current protection state: `ha addons info local_sambanas2 | grep -i protected` → note `ORIG_PROTECTED`
3. Enable protection mode (if not already ON): Supervisor API `POST /addons/local_sambanas2/security {"protected": true}`, then `ha addons restart local_sambanas2` → wait 12 s → health 200
4. Ensure frontend is served at `http://localhost:3080/` — page loads with no JS errors
5. Navigate to Dashboard (`#full-width-tab-0` at desktop viewport `1440x900`); complete the Setup Wizard first if it opens (see 008.002 step 5)
6. Baseline: `GET /api/problems` contains `problem_key: "protected_mode"` with `ignored: false`

**If any preparation step fails** (addon not running, UI not accessible, no `protected_mode` problem), the test must be **skipped**.

## Execution

1. On the Dashboard, expand Actionable Items and assert the "Addon in Protected Mode" card is visible with an **Ignore** button
2. Click **Ignore** → assert the card disappears from the dashboard (toggle "Show Ignored" ON to confirm it is listed with an "Ignored" chip and a **Re-enable** button)
3. Assert backend state: `GET /api/problems/protected_mode` → `ignored: true`, `status: "ignored"`
4. Assert HA silence: no new `srat_problem_protected_mode` persistent notification is created (repairs issue stays ignored); check addon logs for `protected_mode alert` lines showing suppression, not creation
5. Restart the addon (`ha addons restart local_sambanas2`, wait 12 s) → refresh Dashboard → assert the card is still hidden (Show Ignored reveals it as ignored) and `GET /api/problems/protected_mode` still reports `ignored: true`
6. Click **Re-enable** → assert the card reappears immediately while protection is still ON and `GET /api/problems/protected_mode` reports `ignored: false`
7. Restore protection state to `ORIG_PROTECTED` (restart if changed)

**Assertions:**

- Ignore hides the card; backend records `ignored: true` / `status: ignored`
- Ignore survives an addon restart (no re-raise, no HA notification)
- Re-enable restores the card without a restart
- No red error banner; console has no uncaught errors

## Validation

1. Check addon logs after all steps: `ha addons logs local_sambanas2 | tail -n 30 | grep -iE "panic|FATAL"` → empty
2. Confirm final protection state equals `ORIG_PROTECTED`
3. Confirm addon state `started` and health 200

**Success criteria:** Ignore permanently suppresses the protected-mode alert across restarts until explicitly re-enabled, with symmetric UI/backend/HA state at every step.
