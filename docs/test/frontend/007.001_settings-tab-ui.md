# Test Case: 007.001_settings-tab-ui

## Test Objective

Verify Settings tab loads correctly: left `SimpleTreeView` with categories (General, Network→Devices/Access Control, Telemetry, HomeAssistant, App Configuration), right panel shows General by default, search filters tree, selection persists via `localStorage` keys `srat_settings_selected` / `srat_settings_expanded`, WS green, no console errors.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Verify settings reachable: `curl -s http://192.168.0.68:3000/api/settings | jq -e 'has("hostname")'` → true; `curl -s http://192.168.0.68:3000/api/capabilities | jq -e 'has("lib_smart_available")'` → true (if present)
3. Frontend served at `http://localhost:3080/` via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote` → `Bun.serve listening on :3080` and `bun tsc --noEmit` green
4. Clear localStorage baseline then reload: in browser console `localStorage.removeItem("srat_settings_selected"); localStorage.removeItem("srat_settings_expanded")` then reload `http://localhost:3080/`
5. Open devtools: `browser_console_messages` should have no uncaught errors after initial load

**If any preparation step fails** (addon down, settings 404, frontend not ready), **skip**.

## Execution

1. Navigate to `http://localhost:3080/` → wait for App shell; verify NavBar Tabs include `Settings` (`getByRole('tab', {name:/settings/i})` or `#full-width-tab-*`); click `Settings` tab
2. Take screenshot → verify `Settings` search bar visible (`getByPlaceholderText('Search settings...')`) and `Setup Wizard` button; left panel `SimpleTreeView` rendered; right panel heading `General` (`getByRole('heading', {name:/^General$/i})`)
3. Verify tree structure: `browser_snapshot` then `document.querySelectorAll('[role="treeitem"]')` → at least 6 items: `General`, `Network` (parent) with children `Devices`, `Access Control`, `Telemetry`, `HomeAssistant`, `App Configuration`. Parent `Network` is expanded by default (`expandedItems` includes `network` per `DEFAULT_EXPANDED`)
4. Verify right panel default: `General` shows fields `Hostname`, `Workgroup`, `Local Master` switch, `Compatibility Mode`, etc. via `getByLabelText`/`getByRole('switch')`
5. Click `Devices` leaf (`onClick` → `selectedSetting=devices`): verify heading changes to `Devices` (`getByRole('heading', {name:/^Devices$/i})`) and panel shows `Bind all interfaces`, `Interfaces`, `Multi Channel`, `SMB over QUIC`
6. Verify persistence: `localStorage.getItem('srat_settings_selected')` → `devices`; `localStorage.getItem('srat_settings_expanded')` → JSON array
7. Test search filter: type `telemetry` into `Search settings...`; tree should show only `Telemetry` treeitem, others hidden; clear search → full tree returns
8. Search `network` → `Network` parent with children visible; filterNote: search matches both `label` and `settingName`
9. Select `App Configuration` → verify bottom `Apply` bar is hidden (`queryByRole('button', {name:/^Apply$/i})` is null) and panel shows schema-driven fields or `Apply App Configuration` button instead
10. Reload page → verify same selection (`devices` or last selected) remains via localStorage restore; no flash of wrong panel
11. Check WebSocket indicator in NavBar is green and `browser_network_requests` for `/api/settings` returned 200

**Assertions:**
- Settings tab renders tree + default General panel
- Search filters correctly (label + settingName), clear restores
- Selection persists via localStorage and survives reload
- App Configuration hides global Apply bar
- WS green, `/api/settings` 200, no console errors

## Validation

1. Verify mobile drawer: resize to `mobile` viewport (`browser.resize` mobile) → hamburger `MenuIcon` appears (`getByLabelText('open settings navigation')`); click opens drawer with same tree
2. Check tour anchors: `document.querySelector('[data-tutor="reactour__tab4__step0"]')` exists (Settings tab anchor) and step2/step3/step5/step8 anchors present in respective panels
3. Check console: `browser_console_messages` → no `ERROR` or `not wrapped in act` warnings
4. Check logs: `ha addons logs local_sambanas2 | tail -30` and `ha core logs | tail -20` → no new ERROR after navigation
5. Expand/collapse `Network` → `localStorage` `srat_settings_expanded` updates

**Success criteria:** Tree with all categories renders, search/persistence/anchors work, no UI or log errors.
