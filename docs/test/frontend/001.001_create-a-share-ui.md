# Test Case: 001.001_create-a-share-ui

## Test Objective

Verify that the frontend UI allows users to create a new SMB share with the required fields and validates input correctly.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Ensure frontend is served at `http://localhost:3080/` (via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote`)—page loads with no JS errors
3. Navigate to Shares: `http://localhost:3080/` → click Shares tab (`#full-width-tab-2`)
4. Verify the share creation form is loaded via `ShareEditDialog`/`ShareEditForm`: fields "Share Name", "Share Path" (derived from mount), and validation
5. Check that `GET /api/shares` is reachable: `curl -s http://192.168.0.68:3000/api/shares | jq '.'`—should return JSON array
6. Open browser developer tools and verify no JavaScript errors on page load

**If any preparation step fails** (addon not running, UI not accessible, form not loaded), the test must be **skipped**.

## Execution

1. Resolve a free mount point for the new share (avoid 422 on reused path):
   ```bash
   MNT=$(curl -s http://192.168.0.68:3000/api/volumes | jq -c '.[] | select(.id=="ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056") | .partitions["ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2"].mount_point_data | to_entries[0].value')
   TEST_SHARE="ui-test-share-$(date +%s)"
   ```
2. Via UI, trigger Create Share from Volumes (`CREATE SHARE` on the partition) or Shares tab create action—`ShareEditDialog` opens
3. Fill form: Share Name `ui-test-share-*` (use `$TEST_SHARE`), mount derived from `MNT.path` (e.g. `/mnt/ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2`), Description as applicable; submit
4. Wait for UI to show success toast and for `SharesTreeView` to include the new share (group count increments)

**Assertions:**
- Success notification/toast appears after share creation
- New share name `ui-test-share-*` appears in `SharesTreeView` without reload
- Network `POST /api/share` returns 201 and `GET /api/shares` contains the new share
- Browser console has no uncaught errors

## Validation

1. Verify the newly created share via the SRAT API:
   ```bash
   curl -s http://192.168.0.68:3000/api/shares | jq -r ".[].name" | grep "ui-test-share"
   ```
2. Confirm `testparm -s` contains the share block: `ssh root@192.168.0.68 "docker exec app_local_sambanas2 testparm -s 2>&1 | grep -i \"\[.*ui-test-share.*\]\""`
3. Check WS `shares` event: `ws://192.168.0.68:3000/ws` stream contains `event: shares` with the new share within 5 seconds
4. Cleanup: `curl -X DELETE http://192.168.0.68:3000/api/share/${TEST_SHARE}` → 204; verify `GET /api/shares` no longer contains it

**Success criteria:** Share created via UI is verifiable through API, `smb.conf`, and WS; UI updates without reload and cleanup restores baseline.
