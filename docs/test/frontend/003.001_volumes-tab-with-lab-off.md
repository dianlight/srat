# Test Case: 003.001_volumes-tab-with-lab-off

## Test Objective

Verify that the Volumes tab remains visible when experimental_lab_mode is OFF, while lab-gated features (smb.conf view, HDIdle controls) are correctly hidden. This validates the lab feature registry gating introduced in task 051.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` — state should be `started`
2. Verify addon API is reachable: `docker exec addon_local_sambanas2 curl -s http://localhost:64289/api/health` or via `curl -s http://192.168.0.68:3000/api/health` — should return 200 with healthy status
3. Fetch current settings: `curl -s http://localhost:3000/api/settings` or via UI Settings → General — note `experimental_lab_mode` value
4. Set lab mode OFF if needed:
   ```bash
   curl -X PUT http://localhost:3000/api/settings -H "Content-Type: application/json" -d '{"experimental_lab_mode": false}'
   ```
   Or via Settings UI: toggle OFF `Experimental Lab Mode` and Save
5. Verify lab features reflect OFF state:
   ```bash
   curl -s http://localhost:3000/api/lab_features | jq .
   # hdidle.available should be false, smb_conf.available false in production; all alpha features omitted
   ```
6. Ensure frontend is served at `http://localhost:3080/` (via `mise run //frontend:dev:remote`) — page should load with no JS errors
7. Open browser dev tools — verify no uncaught errors on load

**If any preparation step fails** (addon not running, API unreachable, settings not persisted), the test must be **skipped**.

## Execution

1. Navigate to `http://localhost:3080/` and wait for NavBar tabs to render
2. Assert Volumes tab is visible:
   - Query selector `[data-tutor="reactour__tab2__step1"]` or text `Volumes` — should exist and be clickable
   - Take screenshot of NavBar tab bar
3. Assert lab-gated tabs are hidden when lab OFF:
   - Query `smb.conf` tab `[data-tutor="reactour__tab5__step1"]` — should NOT exist / not in DOM
   - If visible, fail
4. Click Volumes tab, wait for volumes page to load
   - Verify no red error banner
   - Verify tree view or "Loading volumes..." resolves
   - Take screenshot of volumes page content
5. Check HDIdle-specific UI is hidden when lab OFF:
   - Dashboard → DiskHealthMetrics: HDIdle suggestion badge `dashboard-hdidle-suggestion-badge` should NOT be in DOM (when disk.is_rotational=true and enabled=no, badge requires labMode)
   - Volumes → HDIdleDiskSettings card "Power Settings" should be hidden in production (getCurrentEnv()==production) — verify `Power Settings` heading not found when lab OFF (or only visible in dev)
   - If in dev build, badge/card visibility should still be gated by labMode=false → not shown
6. Re-enable lab mode for counter-check (optional validation):
   ```bash
   curl -X PUT http://localhost:3000/api/settings -H "Content-Type: application/json" -d '{"experimental_lab_mode": true}'
   ```
   Refresh page and verify `smb.conf` tab appears and HDIdle elements become eligible (when supported disk present)
7. Reset lab mode to original value after execution

**Assertions:**
- Volumes tab is present in NavBar regardless of lab OFF (fail if missing → regression)
- `smb.conf` tab is absent when `hdidle`/`smb_conf` available=false
- `/api/lab_features` returns `available=false` for beta keys when lab OFF
- Volumes page loads without errors and shows volumes tree (or empty state, not error)
- Browser console has no uncaught errors related to lab feature gating
- Network: `GET /api/lab_features` returns 200, `GET /api/volumes` returns 200

## Validation

1. Re-fetch settings and lab_features after toggling to confirm persistence:
   ```bash
   curl -s http://localhost:3000/api/lab_features | jq '.[].key, .[].available'
   ```
2. Check addon logs for errors after UI navigation:
   ```bash
   ha addons logs local_sambanas2 --lines 50
   ```
   No `ERROR` or `panic` introduced by toggling lab mode
3. Check core logs for custom component errors (if any): `ha core logs` — no tracebacks from `custom_components.srat`
4. Verify WebSocket still green/connected indicator after toggling (NavBar secure/lock icon unchanged)
5. Clean up: restore original `experimental_lab_mode` value, leave volumes state unchanged

**Success criteria:** Volumes tab is always visible (lab-independent); lab-gated tabs/features correctly respect `experimental_lab_mode` OFF; no errors in UI, API, or logs; toggling lab mode is persisted and reflected immediately without restart.
