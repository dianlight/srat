# Test Case: 004.007_user-share-chips-enabled-disabled-ui

## Test Objective

Verify the Users tab visually separates enabled from disabled shares in both User Information (view) and Edit User (edit) modes: enabled read/write shares render `success`-colored chips, enabled read-only shares `secondary`, disabled shares render muted `default` chips labeled `<name> (disabled)`. Also verify shares hidden by Settings `standard_share_names` (`status.is_hidden:true`) are excluded from the share selectors and the information view.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Record ORIG share states: `curl -s http://192.168.0.68:3000/api/shares | jq -r '.[] | "\(.name) disabled=\(.disabled) hidden=\(.status.is_hidden)"'`; ensure at least one DISABLED share exists (temporarily `PUT /api/share/<name>/disable` on a scratch share if needed — restore after); if no disabled share can be provided, run the hidden-names half only and document
3. Ensure the test user has the disabled share assigned (read/write or read-only) plus at least one enabled share
4. Frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/`; WS indicator green; no console errors after load

**If any preparation step fails** (UI unreachable, no shares at all), **skip** and document.

## Execution

1. **User Information (view):** Users tab → select the test user → in Read/Write and Read-Only sections assert: enabled shares render colored chips (`success` for read/write, `secondary` for read-only), disabled shares render muted `default` chips labeled `<name> (disabled)`; capture a screenshot as evidence
2. **Edit User (edit):** click Edit → in the Read/Write and Read-Only selectors assert selected tags follow the same color rule; open the dropdown → assert mode-hidden share names (per `standard_share_names`) are NOT offered as options, while disabled shares ARE offered with a muted `(disabled)` label; do NOT save; click Cancel; capture a screenshot as evidence

**Assertions:**

- View mode: enabled vs disabled chips differ in color, disabled labeled `(disabled)`
- Edit mode: tag colors match view mode; hidden names absent from options; disabled names present but muted
- No console errors, `GET /api/shares` and `GET /api/users` 200, WS stays green

## Validation

1. Cleanup: cancel the edit (no save) so no user mutation persists; restore any `disabled` flag changed in preparation (`PUT /api/share/<name>/enable`); verify user shares unchanged via `GET /api/users`
2. Check logs: addon logs no `ERROR`/`panic` from users rendering
3. Record screenshots + `disabled`/`is_hidden` flags from `GET /api/shares` as evidence

**Success criteria:** Colors separate enabled/disabled in both modes, hidden names excluded, no mutations left behind, no log errors.
