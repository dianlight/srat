# Test Case: 003.007_mount-partition-ui

## Test Objective

Verify mounting an unmounted partition through the SRAT UI (Volumes tab `VolumeMountDialog` or Dashboard Actionable Items `MOUNT`): the mount succeeds, the UI reflects `is_mounted:true` without reload, and with protection mode ON the `MOUNT` buttons are disabled instead (see `008.002`).

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Record protection state: `ha addons info local_sambanas2 | grep -i protected` → note `ORIG_PROTECTED`. This case performs the mount-click only when protection is OFF; when ON it asserts the disabled state (no clicks)
3. Pick target: `curl -s http://192.168.0.68:3000/api/volumes | jq -r '.[] | .partitions | to_entries[] | select(.value.mount_point_data == null) | .key'` → note first id as `PART_ID` (must exist and be genuinely unmounted; skip if none). For exfat partitions, load the driver first: `docker exec app_local_sambanas2 modprobe exfat`
4. Frontend at `http://localhost:3080/` (desktop viewport `1440x900` so tabs `#full-width-tab-0..5` are exposed) → Volumes tab loads with `PART_ID` visible

**If any step fails** (no unmounted partition, UI not accessible), **skip**.

## Execution

1. If protection is ON: assert every `MOUNT` button for unmounted partitions is `disabled` (snapshot shows `disabled:true`), take a screenshot, and stop here (result counts as pass for the ON branch; run the OFF branch separately after toggling)
2. If protection is OFF: click the `MOUNT` button for `PART_ID` (Dashboard Actionable Items or Volumes row) → `VolumeMountDialog` opens → confirm with default path → expect success toast, no error banner
3. Verify live refresh: within 10s the row shows mounted state (button flips to `UNMOUNT`/`HIDE` enabled) without manual reload; `GET /api/volumes` shows `is_mounted:true` for the path
4. Verify network: `POST /api/volume/mount` → 200 in browser network requests
5. Unmount to restore baseline: click `UNMOUNT` (or `DELETE /api/volume?mount_path=<path>&force=true` → 204) → row returns to unmounted within 10s

**Assertions:**

- OFF: mount via UI 200, live refresh <10s, unmount restores baseline
- ON: `MOUNT` buttons disabled, no clicks performed
- No red error banner; console has no uncaught errors

## Validation

1. `GET /api/volumes` mount state matches the UI tree after each transition
2. Addon logs `tail -n 20 | grep -iE "panic|FATAL"` → empty
3. Restore protection to `ORIG_PROTECTED` if toggled; confirm `started` + health 200

**Success criteria:** UI mount lifecycle works when OFF (with live refresh), correctly gated when ON, baseline restored, no log errors.
