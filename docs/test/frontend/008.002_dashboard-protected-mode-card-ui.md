# Test Case: 008.002_dashboard-protected-mode-card-ui

## Test Objective

Verify that the Dashboard surfaces the addon protection-mode state (see dianlight/hassio-addons#730): with protection mode ON an explanatory card is shown and all per-partition MOUNT/HIDE actions are disabled; with protection mode OFF the card is absent and mount actions are enabled again.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Record current protection state: `ha addons info local_sambanas2 | grep -i protected` → note `ORIG_PROTECTED`
3. Ensure frontend is served at `http://localhost:3080/` (via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote`) — page loads with no JS errors
4. Navigate to Dashboard: `http://localhost:3080/` → click Dashboard tab (`#full-width-tab-0`)

**If any preparation step fails** (addon not running, UI not accessible), the test must be **skipped**.

## Execution

1. Enable protection mode (if not already ON): `POST /addons/local_sambanas2/security {"protected": true}` via Supervisor API from inside the addon container, then `ha addons restart local_sambanas2` → wait 12 s → health 200
2. Refresh the Dashboard and assert:
   - an "Addon in Protected Mode" card is visible, explaining that no disks can be mounted and pointing at the addon settings toggle
   - every per-partition MOUNT and HIDE button in Actionable Items is `disabled`
3. Take a screenshot of the Dashboard for evidence
4. Disable protection mode: Supervisor API `{"protected": false}`, restart addon, wait 12 s, refresh Dashboard and assert:
   - the protected-mode card is absent
   - MOUNT/HIDE buttons are enabled (for genuinely unmounted partitions)
5. Restore protection state to `ORIG_PROTECTED` (restart if changed) so later cases see the expected baseline

**Assertions:**

- Protected ON: explanatory card present + all MOUNT/HIDE buttons disabled
- Protected OFF: card absent + mount actions enabled
- No red error banner in either state; browser console has no uncaught errors
- `GET /api/volumes` returns 200 in both states (reads are never blocked)

## Validation

1. Check addon logs for errors after both toggles: `ha addons logs local_sambanas2 | tail -n 30 | grep -iE "panic|FATAL"` → empty
2. Confirm final protection state equals `ORIG_PROTECTED`: `ha addons info local_sambanas2 | grep -i protected`
3. Confirm addon state `started` and health 200 after the final restart

**Success criteria:** Dashboard protection-mode gating is symmetric (ON shows card + disables actions, OFF restores both) with no log errors and the original protection state restored.
