# Test Case: 007.007_alerts-settings-category

## Test Objective

Verify the Settings → Alerts category: the three alert toggles (protected mode, add-on configuration changed, custom component) render, persist through save + addon restart, disabling a toggle dismisses its problem and suppresses re-emission, and the custom-component toggle is hidden unless lab mode is on (dev/prerelease builds).

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; health 200
2. Ensure frontend is served at `http://localhost:3080/` — page loads with no JS errors
3. Navigate to Settings tab; complete the Setup Wizard first if it opens (see 008.002 step 5)
4. Record baseline settings: `GET /api/settings` → note `alert_protected_mode`, `alert_addon_config_changed`, `alert_custom_component`, `experimental_lab_mode`
5. Record baseline problems: `GET /api/problems` → note existing keys

**If any preparation step fails** (addon not running, UI not accessible), the test must be **skipped**.

## Execution

1. In Settings, select the **Alerts** category → assert three labeled switches are reachable (with lab mode ON: "Protected mode alert", "Add-on configuration changed alert", "Custom component alerts"; with lab mode OFF the custom-component switch is absent)
2. Toggle **Protected mode alert** OFF → Apply → assert `PUT /api/settings` 200 and `GET /api/settings` returns `alert_protected_mode: false`
3. Assert side effect: `GET /api/problems` no longer contains `protected_mode` (dismissed on disable)
4. Restart the addon, wait 12 s → assert `GET /api/settings` still returns `alert_protected_mode: false` (persisted) and no `protected_mode` problem is re-raised
5. Toggle **Protected mode alert** back ON → Apply → assert the problem reappears on the next reconcile (restart addon if needed) with `ignored: false`
6. Lab gating: set `experimental_lab_mode` OFF → Apply → reopen Alerts → assert the custom-component toggle is hidden; set lab mode back ON → assert it reappears (dev/prerelease builds only)
7. Restore all toggles modified above to their baseline values → Apply

**Assertions:**

- Alerts category renders all applicable toggles; save/apply/reset behave like other settings panels
- Toggle values persist across addon restart
- Disabling an alert dismisses its problem and blocks re-emission; re-enabling restores it
- Custom-component toggle visibility follows lab mode; no console errors

## Validation

1. Check addon logs: `ha addons logs local_sambanas2 | tail -n 30 | grep -iE "panic|FATAL"` → empty
2. Confirm `GET /api/settings` matches the recorded baseline for all four fields
3. Confirm addon state `started` and health 200

**Success criteria:** Alert toggles persist, disabling suppresses emission, re-enabling restores, and lab gating hides the custom-component toggle — with settings and problems back at baseline.
