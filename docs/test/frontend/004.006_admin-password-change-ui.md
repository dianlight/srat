# Test Case: 004.006_admin-password-change-ui

## Test Objective

Verify the admin password can be changed through the Users UI (`UserEditForm` via `PUT /useradmin`): the new credential authenticates over Samba, the old one stops working, and the change is restored afterwards so the recorded test-box password stays valid.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Record current admin: `curl -s http://192.168.0.68:3000/api/users | jq -r '.[] | select(.is_admin==true) | .username'` → `ORIG_ADMIN`; record the **known working password** as `ORIG_PASS` (current test-box value; do not proceed if unknown — ask the operator)
3. Generate test password: `TEST_PASS="Adm$(date +%s | tail -c 5)!"` (record it); frontend at `http://localhost:3080/` → `USERS` tab shows `ORIG_ADMIN` in `Administrators`
4. Baseline Samba auth: `docker exec app_local_sambanas2 smbclient -L //127.0.0.1 -U $ORIG_ADMIN%$ORIG_PASS` → shares listed (proves `ORIG_PASS` before mutation)

**If any step fails** (no admin, `ORIG_PASS` unknown or rejected, UI not accessible), **skip**.

## Execution

1. Navigate `USERS` → expand `Administrators` → open `ORIG_ADMIN` details → click `Edit User`
2. Fill `Password` and `Repeat Password` with `$TEST_PASS` (leave username unchanged) → `SAVE CHANGES` → expect network `PUT /useradmin` → 200 and success toast
3. Verify new credential: `docker exec app_local_sambanas2 smbclient -L //127.0.0.1 -U $ORIG_ADMIN%$TEST_PASS` → shares listed
4. Verify old credential rejected: `smbclient -L //127.0.0.1 -U $ORIG_ADMIN%$ORIG_PASS` → `NT_STATUS_LOGON_FAILURE` (or equivalent auth error)
5. Verify backend: `GET /api/users` admin `has_default_password:false`; `pdbedit -L | grep $ORIG_ADMIN` → present

**Assertions:**

- `PUT /useradmin` 200 via UI; new password authenticates, old password fails
- No other user or share state changed (`GET /api/shares` count unchanged)

## Validation

1. **Restore:** repeat the edit with `ORIG_PASS` in both password fields → 200; `smbclient` with `ORIG_PASS` works again, with `TEST_PASS` fails
2. Logs: `ha addons logs local_sambanas2 | tail -n 20 | grep -iE "panic|FATAL|ERROR"` → empty (auth-failure lines for the negative check are expected)
3. Confirm `GET /api/users` admin unchanged apart from password; record all status codes

**Success criteria:** Password change lifecycle via UI succeeds both ways, Samba auth follows, original credential restored, no log errors.
