# Test Case: 001.011_share-name-dash-parity-ui-api

## Test Objective

Verify share-name character acceptance is consistent between the UI create dialog and the API: names the backend accepts (e.g. containing `-`, valid per Samba/NetBIOS and observed 201 via `POST /api/share`) must not be rejected client-side by `ShareEditDialog` validation ("Share name can only contain letters, numbers, and underscores"). Found during the 001.001 remote run (2026-10-13): `ui-test-share-<ts>` (dashes) got 201 via API but the UI flags dashes invalid.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Free mount: pick a mounted partition with `share==null` from `GET /api/volumes` → save `MNT` object (same jq pattern as `001.001` step 4)
3. Frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/`; no console errors after load
4. Test name: `TEST_SHARE="parity-$(date +%s)"` (contains dashes)

**If any preparation step fails** (no free mount, UI unreachable), **skip**.

## Execution

1. **API accepts dashes:** `POST /api/share` with `{name:$TEST_SHARE, mount_point_data:$MNT, usage:"media", guest_ok:true}` → expect 201; `GET /api/shares` contains it; `testparm -s` shows the section
2. **UI validation:** Shares tab → Create new share → type `$TEST_SHARE` into Share Name → record whether the field is flagged invalid and which message shows
3. **Parity assertion:** both surfaces agree — either both accept or both reject with the same rule. Divergence (API 201 + UI invalid) = fail, file/link bug

**Assertions:**

- API result and UI validation agree on dash-containing names
- If both accept: UI-created dash name round-trips through API + smb.conf
- No console errors during the dialog flow

## Validation

1. Cleanup: `DELETE /api/share/$TEST_SHARE` → 204; verify gone from `GET /api/shares` and `testparm -s`
2. Check addon logs: `tail -n 20 | grep -iE "panic|FATAL"` → empty
3. Record the exact UI validation message and API status as evidence

**Success criteria:** UI and API agree on the share-name character set; cleanup complete; no log errors.
