# Test Case: 001.011_share-name-dash-parity-ui-api

## Test Objective

Verify that the share-name character set accepted by the frontend UI matches the backend API. Specifically, names containing hyphens (e.g. `parity-check-1`) must be accepted by both the UI validation and the API, so users can recreate via the UI what the API created (issue #1400).

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Ensure frontend is served at `http://localhost:3080/` (via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote`)—page loads with no JS errors
3. Navigate to Shares: `http://localhost:3080/` → click Shares tab (`#full-width-tab-2`)
4. Record baseline share count: `curl -s http://192.168.0.68:3000/api/shares | jq length` → `BASE_COUNT`

**If any preparation step fails** (UI not accessible, API unreachable), the test must be **skipped**.

## Execution

1. Click Create new share (`#create_new_share`) — `ShareEditDialog` opens
2. Fill Share Name with `parity-check-1` (contains hyphens)
3. Open the Volume selector and select a mounted, write-supported volume
4. Click Create

**Assertions:**

- The Share Name field does NOT show a validation error for `parity-check-1`
- The form submits successfully (no client-side rejection)
- `GET /api/shares` contains a new share named `parity-check-1`
- Browser console has no uncaught errors

## Validation

1. Verify the share was created:
   ```bash
   curl -s http://192.168.0.68:3000/api/shares | jq '.[] | select(.name=="parity-check-1")'
   ```
2. Confirm the share appears in `smb.conf`: `ssh root@192.168.0.68 "docker exec app_local_sambanas2 testparm -s 2>&1 | grep -i '\[parity-check-1\]'"`
3. Clean up: `curl -X DELETE http://192.168.0.68:3000/api/share/parity-check-1` → 204
4. Verify share count returns to `BASE_COUNT`: `curl -s http://192.168.0.68:3000/api/shares | jq length`

**Success criteria:** A share name containing hyphens is accepted by both the UI and the API, and the created share is verifiable through the API and `smb.conf`.
