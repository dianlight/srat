# Test Case: 008.001_dashboard-news-ui

## Test Objective

Verify the Dashboard "Latest News" widget shows only real news with an abstract: each item has a per-type icon (release vs announcement) and a non-empty abstract; release items are strictly newer than the running build (`hello.build_version` via `semver.gt`); a "See all news" link under the list opens the full announcements archive so older releases and announcements stay accessible.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Frontend served at `http://localhost:3080/` via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote` → `Bun.serve listening on :3080` and `bun tsc --noEmit` green
3. GitHub API reachable: `curl -s "https://api.github.com/repos/dianlight/srat/discussions?category=announcements" | jq -e 'type == "array"'` → true
4. Capture the running build version from the WS hello frame (used for the version-gate assertion):
   ```bash
   curl -s -H "Connection: Upgrade" -H "Upgrade: websocket" http://192.168.0.68:3000/ws | grep -a '^data:' | head -5
   ```
   → one `data:` frame parses as JSON with `.hello.build_version` (e.g. `2026.9.0-dev.15`); export as `RUNNING_VERSION`
5. Open devtools baseline: `browser_console_messages` should have no uncaught errors after initial load

**If any preparation step fails** (addon down, frontend not ready, GitHub API unreachable), **skip**.

## Execution

1. Navigate to `http://localhost:3080/` → wait for App shell; expand the `Welcome to SRAT` intro card (click `expand` button) if collapsed
2. Verify the `Latest News:` heading is visible; below it each news item shows an icon plus a title link plus a plain-text abstract (`data-testid="dashboard-news-abstract"`, non-empty, no raw `##` markdown)
3. Verify per-type icons: release items use `data-testid="dashboard-news-release-icon"`, announcements use `data-testid="dashboard-news-announcement-icon"`
4. Verify the version gate: for every visible item whose title matches `Release <ver>`, `semver.gt(<ver>, $RUNNING_VERSION)` is true. Compute the expected set independently (run from `frontend/` so `require("semver")` resolves):
   ```bash
   curl -s "https://api.github.com/repos/dianlight/srat/discussions?category=announcements" -o /tmp/srat_news.json
   cat > ./check-news-expected.cjs <<'EOF'
   const { readFileSync } = require("node:fs");
   const semver = require("semver");
   const norm = (raw) => {
     const c = String(raw || "").trim().replace(/^[vV]/, "").replace(/[),.\]]+$/, "");
     return semver.valid(c) || (semver.coerce(c) || {}).version || null;
   };
   const running = norm(process.env.RUNNING_VERSION);
   if (!running) { console.error("bad RUNNING_VERSION"); process.exit(2); }
   const cutoff = Date.now() - 92 * 864e5;
   const out = [];
   for (const d of JSON.parse(readFileSync("/tmp/srat_news.json", "utf8"))) {
     if (new Date(d.created_at).getTime() <= cutoff) continue;
     if (!String(d.body || "").trim()) continue;
     const m = /^Release\s+(\S+)/i.exec(String(d.title).trim()) || /releases\/tag\/([^\s"'<>)]+)/.exec(d.body);
     if (m) {
       const v = norm(m[1]);
       if (!v || !semver.gt(v, running)) continue;
     }
     out.push(d.title);
   }
   console.log(out.slice(0, 5).join("\n"));
   EOF
   RUNNING_VERSION="$RUNNING_VERSION" node ./check-news-expected.cjs
   rm ./check-news-expected.cjs /tmp/srat_news.json
   ```
   → every printed title is visible in the UI list; no visible `Release <ver>` title is missing from this list
5. Verify the `See all news` link (`data-testid="dashboard-news-see-all"`): `href` is `https://github.com/dianlight/srat/discussions/categories/announcements`, `target="_blank"`; it renders even when the filtered list is empty and next to the warning when the GitHub fetch fails (offline check is optional)
6. Take a screenshot of the expanded news section for evidence

**Assertions:**

- Every visible item has an icon matching its type and a non-empty plain-text abstract
- Every visible release is strictly newer than the running build; older releases are hidden
- `See all news` links to the announcements archive and opens in a new tab
- WS indicator green, no console errors during the check

## Validation

1. Check console: `browser_console_messages` → no `ERROR` or uncaught fetch failures (a GitHub rate-limit 403 is environmental, not a failure — note it and still expect the `See all news` link)
2. Check logs: `ha addons logs local_sambanas2 | tail -30` → no new ERROR after navigation (frontend-only change, no backend traffic beyond existing APIs)
3. Reload page → news list and link render identically (RTK cache `keepUnusedDataFor: 3600`); no flash of wrong content

**Success criteria:** Icons + abstracts render per type, version gate matches the independently computed set, archive link is correct and always present, no UI or log errors.
