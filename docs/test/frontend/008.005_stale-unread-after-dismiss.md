# Test Case: 008.005_stale-unread-after-dismiss

## Test Objective

Verify the header notification badge never counts stale terminal problem notifications: after a `protected_mode` problem reaches a terminal state (`dismissed`, `fixed`, `deleted`) or `ignored`, its toast entry disappears from the bell list and the badge drops immediately without opening the bell (covers the `toast.dismiss` stale-`unreadCount` path from issue 1239).

## Preparation

1. Ensure the SRAT addon is running: `ha apps info local_sambanas2` → `started`; health 200
2. Ensure protection mode is ON and `protected_mode` problem is active with `ignored: false` (re-enable via API if needed)
3. Ensure frontend is served at `http://localhost:3080/` — page loads with no JS errors
4. Navigate to Dashboard (desktop viewport `1440x900`); complete the Setup Wizard first if it opens (see 008.002 step 5)
5. Baseline: record the header badge count next to the notification bell

**If any preparation step fails** (addon not running, UI not accessible, no active problem), the test must be **skipped**.

## Execution

1. With an active `protected_mode` toast visible, dismiss it via API to a terminal state (e.g. resolve/fix the condition or `DELETE` the problem) → assert the bell list no longer shows the entry
2. Assert the header badge count decreases immediately (no bell open required); a stale `1` with an empty list is a fail (issue 1239 pattern)
3. Repeat with Ignore → assert card hides, bell list hides the entry, and badge drops by one
4. Re-enable (`ignored: false, status: created`) → assert card returns and badge is restored without restart
5. Restore: leave the problem un-ignored (`ignored: false`) unless the suite baseline requires otherwise

**Assertions:**

- Terminal (`dismissed`/`fixed`/`deleted`) and `ignored` problems are excluded from badge and bell list
- Badge derives from visible notifications, not a stale `unreadCount`
- Re-enable restores both card and badge without a restart
- No red error banner; console has no uncaught errors

## Validation

1. `GET /api/problems/protected_mode` → `ignored: false` (baseline state)
2. Check addon logs: `ha apps logs local_sambanas2 | tail -n 30 | grep -iE "panic|FATAL"` → empty
3. Confirm addon state `started` and health 200

**Success criteria:** Badge and bell list follow server terminal/ignore state symmetrically with no stale count; if the badge diverges, file it as a bug with a screenshot and mark the case fail with evidence.
