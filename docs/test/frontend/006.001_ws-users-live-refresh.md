# Test Case: 006.001_ws-users-live-refresh

## Test Objective

Verify WebSocket live refresh for `users` events: after `POST /user` and `DELETE /user/{username}` the frontend `UsersTreeView` updates within 10s without manual reload, and WS payload freshness matches `GET /api/users` (no stale cache, see #971).

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200; `curl -s http://192.168.0.68:3000/api/users | jq length` → baseline `BASE_COUNT` (≥1, includes admin)
2. Frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/` → `Users` tab loads, `WS` indicator green in NavBar (check via `browser_snapshot` header status or `slog-http` no disconnect)
3. Start background WS listener (ground truth, per Cat 4 WS pre-check pattern from `004` instructions):
   ```bash
   # Plain no-auth WS at 3000/ws, SSE-formatted text frames id:/event:/data: split on \n
   # Record every `users` event plus REST /api/users for freshness comparison
   # Use socat or node: `node -e "import('ws')... ws://192.168.0.68:3000/ws"`
   # Save events with timestamp to /tmp/ws_users.log
   ```
   Alternative: use `curl` + `websocat` if available. Keep listener running for entire execution.
4. Verify no stale WS: trigger a dummy `GET /api/users` → compare with last `users` event `data:` payload (if any) within 2s — they should match or listener has no prior event yet (initial `hello` only)
5. Generate unique user: `TEST_USER="ws$(date +%s | tail -c 6)"` (≤12 chars, `^[a-zA-Z0-9 _-]+$`), `TEST_PASS="WsPass$(date +%s | tail -c 4)!"` (≥4); ensure `GET /users` does not contain it; save for cleanup

**If any step fails** (WS not connecting, no admin), **skip** and note.

## Execution

1. Navigate `http://localhost:3080/` → `USERS` → snapshot `Users` title and tree `Administrators` group; note `BASE_COUNT` chip
2. **Create via API (background) while UI is open:** `curl -s -X POST http://192.168.0.68:3000/api/user -H "Content-Type: application/json" -d "{\"username\":\"$TEST_USER\",\"password\":\"$TEST_PASS\",\"is_admin\":false}"` → 201; record `T_CREATE=$(date +%s)`
3. **Live refresh assertion (<10s):** poll UI tree every 1s for up to 10s: `browser_snapshot` text should include `$TEST_USER` or inspect `#mui-tree-view-2-$TEST_USER` appears without manual reload; also check `Users 1` → `Users 2` count increments if `BASE_COUNT==1` admin+0 users before (or `group-users` appears if first regular user)
   - If not visible within 10s → **fail** (WS live refresh broken, see W02/W06)
   - Record `T_VISIBLE=$(date +%s)` and duration `T_VISIBLE - T_CREATE` must be <10
4. **WS freshness assertion:** within 2s of visibility, compare WS last `users` event payload (`jq -r --arg u "$TEST_USER" '.[] | select(.username==$u) | .username'`) with `curl -s http://192.168.0.68:3000/api/users | jq -r --arg u "$TEST_USER" '.[] | select(.username==$u) | .username'` → both `$TEST_USER`; if WS payload stale (missing user) → fail W06 (stale broadcast, see #971)
5. **Click new user:** `#mui-tree-view-2-$TEST_USER > div > div > p` → details panel shows `No shares assigned` or assigned shares; verify `UserDetailsPanel` appears without reload
6. **Delete via API while UI open:** `curl -s -X DELETE http://192.168.0.68:3000/api/user/$TEST_USER -w "\n%{http_code}\n"` → 204; record `T_DELETE=$(date +%s)`
7. **Live delete refresh (<10s):** poll tree for disappearance of `$TEST_USER` (inspect `#mui-tree-view-2-$TEST_USER` missing, `group-users` chip decrements or group removed) without reload; must happen <10s, record `T_GONE`
8. **WS delete freshness:** last `users` event after delete must no longer contain `$TEST_USER`; compare with `GET /users` similarly within 2s

**Assertions:**
- Create/delete reflect in UI <10s via WS, no manual `users.refetch()` needed beyond automatic RTK/WS subscription
- WS payload freshness matches REST within 2s for both create and delete
- Tree counts and details update correctly

## Validation

1. **Reconnect after drop (W04):** kill WS listener, restart it, then create another temp user `ws2$(date +%s | tail -c 4)` → still visible <10s (reconnect works); delete it
2. Logs: `ha addons logs local_sambanas2 | tail -30` → no `WebSocket Process Closed` error beyond expected disconnect/reconnect; no `ERROR` for `users` handler
3. Check `browser_console_messages` → no uncaught WS errors, `RTK Query` cache not stale
4. Cleanup: ensure `GET /users` length == `BASE_COUNT`; if `$TEST_USER` still present `DELETE` again; `pdbedit -L | grep $TEST_USER` → not found; stop background WS listener and save log to `evidence/ws_users.log`

**Success criteria:** UI live-refresh <10s for both create and delete, WS payload fresh vs REST, reconnect works, no log errors, baseline restored.
