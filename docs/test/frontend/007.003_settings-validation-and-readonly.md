# Test Case: 007.003_settings-validation-and-readonly

## Test Objective

Verify Settings validation (hostname/workgroup regex, allow_hosts IP/CIDR, telemetry required) blocks `Apply`, shows inline errors, and read-only mode disables all controls and hides `Apply`.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/` → Settings tab → General visible; `bun tsc --noEmit` green
3. Capture read_only flag: `curl -s http://192.168.0.68:3000/api/settings | head` and WS `hello.read_only`; for validation part ensure `read_only:false`; for readonly part will simulate via `read_only:true` response or check current env (if true, skip validation part)
4. Record baseline `GET /api/settings` to restore after

**If any preparation step fails** (API unreachable, frontend not ready), **skip**.

## Execution

1. **Hostname required:** Navigate Settings→General → clear `Hostname` input (`getByLabelText(/Hostname/i)`), blur → `getByText('Hostname is required.')` appears; `Apply` stays disabled or PUT not fired on submit attempt (form `mode:onBlur` prevents submit if invalid)
2. **Hostname regex:** type `-bad-` or `bad_` (invalid per `HOSTNAME_REGEX` `^[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?$`) → error `Invalid hostname...` shown
3. **Hostname maxLength:** attempt 64-char string (`printf 'a%.0s' {1..64}`) → `Hostname cannot exceed 63 characters.` (or browser truncates)
4. **Workgroup regex:** clear Workgroup, type `bad workgroup!` (contains space + !, fails `WORKGROUP_REGEX` `^[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,13}[a-zA-Z0-9])?$`) → error `Invalid workgroup...`; test valid `TEST-WG1` passes
5. **Access Control:** navigate to `Network` → `Access Control` (`getByText('Access Control')` click) → heading `Access Control`; try adding invalid chip `not-an-ip` to `MuiChipsInput` (`Allow Hosts`) → chip rejected or helper shows `Invalid entry: "not-an-ip". Only IPv4/IPv6 addresses or CIDR...` on Apply attempt; valid `192.168.1.0/24` and `::1` accepted; required check: deleting all chips → `Allow Hosts cannot be empty.` on submit
6. **Telemetry:** navigate to `Telemetry` → required/autocomplete? Verify at least one option selectable; if empty required message appears
7. **Network Devices:** `Devices` → verify `bind_all_interfaces` switch and `interfaces` list; toggling dirties form and enables Apply (smoke)
8. Attempt `Apply` with valid data (e.g. workgroup `TWG1`) → `PUT /api/settings` 200; with invalid field focused, `Apply` should not succeed (no PUT or 4xx validation)
9. **Read-only simulation:** if env supports `read_only:true` (check `useGetServerEventsQuery` mock or set via addon option `read_only` if available), verify: all `TextFieldElement`/`Switch` disabled (`toBeDisabled()`), `Apply`/`Reset` disabled regardless of dirty, form `disabled: readOnly` propagates

**Assertions:**

- Invalid hostname/workgroup shows regex error and blocks commit
- Invalid allow_hosts chip shows IP/CIDR error; empty shows required
- Valid entries pass and PUT succeeds
- Read-only disables controls

## Validation

1. Restore baseline settings via `PUT /api/settings` with original payload → 200
2. Check console: no `act` warnings despite validation switches
3. Check logs: no new ERROR after validation attempts
4. Verify `false` boolean handling: setting `allow_guest:false` or `local_master:false` still sent as `false` not omitted (inspect PUT payload via `browser_network_requests`)
5. Clean localStorage search/persistence keys if changed

**Success criteria:** All validation rules enforced inline, no bypass, readOnly disables, no log errors.
