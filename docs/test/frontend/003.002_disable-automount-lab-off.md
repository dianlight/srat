# Test Case: 003.002_disable-automount-lab-off

## Test Objective

Verify DISABLE AUTOMATIC MOUNT action for a mounted data partition with lab mode OFF. Prefers WD PC SN740 -part2 (`ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2`, ext4, 2 GB) if present; otherwise asks user which partition to use (see Preparation step 4). Lab OFF must not hide Volumes tab; action must work and persist via API, with cleanup (re-enable).

## Preparation

1. Addon running: `ha apps info local_sambanas2` → `state: started`; `docker logs app_local_sambanas2 | grep Version` → `c1bed217`
2. Lab OFF: `curl -s http://localhost:64289/api/settings | jq .experimental_lab_mode` → `false`. If `true`, set via full Settings PUT (see 003.001 step 4). Verify `curl -s http://localhost:64289/api/lab_features | jq '.[] | select(.key=="smb_conf") | .available'` → `false`
3. Frontend at `http://localhost:3080/` via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote` → `bun tsc --noEmit` green, `App → http://localhost:3080` visible, WS `ws://192.168.0.68:3000/ws` via socat. Snapshot Tabs: `VOLUMES` present, `SMB.CONF` absent.
4. Determine test partition `TEST_PARTITION_ID` / `TEST_MOUNT_PATH` (generalized—WD part2 is preferred, not required):
   ```bash
   curl -s http://192.168.0.68:3000/api/volumes | jq -r '.[] | .partitions | to_entries[] | select(.value.mount_point_data | length>0) | "\(.key)\t\(.value.mount_point_data | to_entries[0].value.path)\t\(.value.fstype)\t\(.value.size)"' | column -t
   ```
   - If `ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2` (`/mnt/ata-WD...-part2`, ext4, 2 GB) exists and `is_mounted:true`, use it:
     `TEST_PARTITION_ID=ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2`, `TEST_MOUNT_PATH=/mnt/ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2`, `WD_DISK_ID=ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056`
   - **Otherwise ask user** via question tool (single-choice) with the candidate list above: `Which partition should this test use? (prefer ext4, mounted, is_write_supported:true, not system)`—candidates are filtered to `host_mount_point_data=={}` and `system==false`. If no mounted candidates, prompt to mount one first via `POST /api/volume/mount` or UI MOUNT.
   - Export for later steps: `export TEST_PARTITION_ID TEST_MOUNT_PATH` (and `WD_DISK_ID` if WD, else the disk `id` containing the chosen partition).
5. Verify chosen partition state: `curl -s http://192.168.0.68:3000/api/volumes | jq --arg pid "$TEST_PARTITION_ID" '.[] | select(.partitions[$pid]!=null) | .partitions[$pid] | {is_mounted: (.mount_point_data|to_entries[0].value.is_mounted == true), automount: (.mount_point_data|to_entries[0].value.is_to_mount_at_startup)}'` → should be `is_mounted:true, automount:true` (DISABLE button visible). If not, mount + enable via API/UI first (`POST /api/volume/mount` or `PATCH /api/volume/settings` with `is_to_mount_at_startup:true`).
   Note: use `is_mounted == true` (NOT `mount_point_data|length>0`)—the map is the persisted mount config and survives unmount; `is_mounted` is omitted from JSON when `false` (`omitempty`, see #1009).
6. `lsof -nPiTCP:3080` → listening, `curl -H "Origin: http://localhost:3080" http://192.168.0.68:3000/api/volumes -v` → `Access-Control-Allow-Origin: http://localhost:3080`

**If any preparation fails**, skip and document.

## Execution

1. Navigate `http://localhost:3080/` → snapshot `#full-width-tab-1` `VOLUMES` exists. Click `VOLUMES`.
2. In Volumes tree, expand the disk containing `$TEST_PARTITION_ID` (e.g. `WD PC SN740` for WD part2) → select `$TEST_PARTITION_ID` (use `$TEST_MOUNT_PATH` for verification). Detail panel → `Partition Information` shows `Mounted`, `Mount Point $TEST_MOUNT_PATH • Auto-mount`, Actions row has `DISABLE AUTOMATIC MOUNT` (if `automount:true`; otherwise `ENABLE`).
3. Click `DISABLE AUTOMATIC MOUNT` → toast `Automount updated for this volume.` Snapshot after.
4. Verify via API: `curl -s http://192.168.0.68:3000/api/volumes | jq --arg pid "$TEST_PARTITION_ID" '.[] | select(.partitions[$pid]!=null) | .partitions[$pid].mount_point_data | to_entries[0].value | {is_to_mount_at_startup, is_mounted}'` → `is_to_mount_at_startup:false`, `is_mounted:true`.
5. Verify WS: `curl -H "Connection: Upgrade" http://192.168.0.68:3000/ws` stream contains `event: volumes` with same `is_to_mount_at_startup:false` within 2 seconds (match REST; see #971).

**Assertions:**
- VOLUMES tab present with lab OFF
- DISABLE button clickable, no `TS6133` console error
- API `is_to_mount_at_startup` false after click
- WS payload matches REST

## Validation

1. Re-enable for cleanup: click `ENABLE AUTOMATIC MOUNT` (same button toggles) → API `is_to_mount_at_startup` → `true` again. Verify WS again.
2. Logs: `docker logs app_local_sambanas2 | tail -n 20` → no `ERROR/panic` for volume settings.
3. Leave lab OFF (per manifest). Volume tree still shows partition mounted.

**Success criteria:** DISABLE toggles `is_to_mount_at_startup` false→true with lab OFF, Volumes tab remains, no errors.
