# Test Case: 007.004_settings-telemetry-and-homeassistant

## Test Objective

Verify Settings Telemetry and HomeAssistant panels: Telemetry mode select persists via `PUT /api/settings`, HomeAssistant switches (`export_stats_to_ha`, `ha_use_nfs`) toggle, persist through reload and addon restart, and respect `read_only:false`.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Fetch baseline: `ORIG=$(curl -s http://192.168.0.68:3000/api/settings)`; note `telemetry_mode`, `export_stats_to_ha`, `ha_use_nfs`
3. Frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/` → Settings tab loads; `bun tsc --noEmit` green, WS green
4. Verify initial panel: `General` selected; ensure `read_only:false` (if true skip)
5. Clear dirty: reload, verify `Apply`/`Reset` disabled

**If any preparation fails** (settings unreachable, read_only true), **skip**.

## Execution

1. Navigate `http://localhost:3080/` → Settings → click `Telemetry` (`mui-tree-view-2-telemetry`) → heading `Telemetry` appears; panel shows `Telemetry Mode` select (options `Disabled`, `Anonymous`, etc. per `TelemetryPanel.tsx`)
2. Change `Telemetry Mode` to opposite of baseline (e.g. `Disabled` → `Anonymous` if available) → verify dirty: `Apply`/`Reset` enabled
3. Click `Apply` → `PUT /api/settings` 200, `reset(res)` clears dirty (`Apply` disabled), `GET /api/settings` shows new `telemetry_mode`
4. Reload page → `Telemetry` still shows new mode (values from `useGetApiSettingsQuery`)
5. Navigate to `HomeAssistant` (`mui-tree-view-2-homeassistant`) → heading `HomeAssistant` → verify switches `Export Stats to HA` and `Use NFS` reflect `ORIG`; toggle `export_stats_to_ha` (or `ha_use_nfs`) → dirty enabled
6. Click `Apply` → 200, verify `GET` shows toggled bool (check `false` not omitted: `jq -e 'has("export_stats_to_ha")'` true)
7. Restart addon: `ha addons restart local_sambanas2` → wait 12s → `curl -s http://192.168.0.68:3000/api/health` 200 → `curl -s http://192.168.0.68:3000/api/settings | jq .telemetry_mode,.export_stats_to_ha` still new values
8. Reload UI → Telemetry/HomeAssistant panels still show new values

**Assertions:**

- Select/switch changes dirty, Apply 200, GET reflects, survives reload+restart, `false` preserved

## Validation

1. Cleanup: restore `ORIG` via `curl -X PUT http://192.168.0.68:3000/api/settings -H "Content-Type: application/json" -d "$ORIG"` → 200; verify `GET` equals `ORIG`
2. Check logs: `ha apps logs local_sambanas2 | tail -30` → no `ERROR`; `mdns_service` reconfigure only if hostname changed, otherwise no samba restart
3. Check `PUT` payload via `browser_network_requests` contains `telemetry_mode` and `export_stats_to_ha:false` explicitly, not omitted
4. Verify WS still green, no console `act` warnings
5. Record evidence: PUT request bodies, GET after, screenshot of Telemetry panel

**Success criteria:** Telemetry and HA switches persist through UI → API → restart, no log errors.
