# Test Case: 004.002_create-user-ui

## Test Objective

Verify CREATE USER via UI: `Users` → `AddIcon` button (`#create_new_user`) opens `UserEditDialog` → fill `UserEditForm` (username, password, repeat, read/write shares) → submit `Create User` → toast success → `GET /api/users` contains new user and `pdbedit -L` shows entry.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Verify shares available for assignment: `curl -s http://192.168.0.68:3000/api/shares | jq -r '.[].name'` → at least one non-internal; save `TEST_SHARE=$(... | head -n1)`
3. Ensure frontend at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/` → `Users` tab loads with no errors
4. Generate unique name: `TEST_USER="u$(date +%s | tail -c 6)"` (satisfies `^[a-zA-Z0-9 _-]+$`, min 2 chars); `TEST_PASS="Aa$(date +%s | tail -c 5)!"` (≥4 chars); export
5. Ensure no existing user: `curl -s http://192.168.0.68:3000/api/users | jq -r --arg u "$TEST_USER" '.[] | select(.username==$u) | .username'` → empty; if exists DELETE first

**If preparation fails**, skip.

## Execution

1. Navigate to `http://localhost:3080/` → click `Users` tab → take screenshot (before)
2. Click `Create new user` button (`getByLabelText('Create new user')` / `#create_new_user`) → dialog opens with title `New User` (`getByText('New User')`) and form fields: `Username`, `Password`, `Repeat Password`, `Read/Write Shares`, `Read-Only Shares`
3. Fill form:
   - `Username` → `$TEST_USER` (use `browser_fill` or `userEvent.type` via `browser_eval` on `input[name="username"]`)
   - `Password` → `$TEST_PASS` (input `name="password"`)
   - `Repeat Password` → `$TEST_PASS` (input `name="password-repeat"`)
   - `Read/Write Shares` → select `$TEST_SHARE` via Autocomplete: click input, type `$TEST_SHARE`, press Enter (verify chip appears `color="success"`)
   - Verify client validation: mismatch password → `Passwords do not match` error; short username (<2) → `at least 2 characters`; invalid chars → pattern error
4. Submit: click `Create User` (`type="submit"`, `getByRole('button',{name:/create user/i})`) → verify `browser_network_requests` shows `POST /api/user` → 201 with body `{"username":"$TEST_USER",...}`; toast `User $TEST_USER created successfully` appears (`getByText(/created successfully/i)`)
5. Dialog closes automatically (`showCreateDialog=false`); verify UI refetch: `UsersTreeView` now contains `$TEST_USER` in `group-users` (expand group if needed, `localStorage["users.expandedGroups"]` includes `group-users`)
6. Click `$TEST_USER` leaf → `UserDetailsPanel` shows username, `1 share` chip, RW shares list contains `$TEST_SHARE`
7. Verify backend ground truth: `curl -s http://192.168.0.68:3000/api/users | jq --arg u "$TEST_USER" '.[] | select(.username==$u) | {username,rw_shares,is_admin}'` → `rw_shares` includes `$TEST_SHARE`; `docker exec addon_local_sambanas2 pdbedit -L | grep $TEST_USER` → found

**Assertions:**

- Dialog opens/closes correctly, form validation fires before submit, `Create User` disabled when `!isDirty` then enabled after typing
- POST 201, toast shown, tree updates without manual reload, backend GET and pdbedit confirm
- Shares deduplication: selecting same share in RW disables it in RO (`getOptionDisabled`)

## Validation

1. Negative: try duplicate → reopen create, enter same `$TEST_USER` + new pass → POST 409 → toast `Error creating user $TEST_USER: ... already exists` (not unhandled)
2. Negative: try empty password → clear password fields → `Password is required` rule fires (required when `doCreate:true`) → submit blocked
3. Logs: `ha addons logs local_sambanas2 | tail -30` → no ERROR/panic for this flow; core logs clean
4. Cleanup: `curl -X DELETE http://192.168.0.68:3000/api/user/$TEST_USER` → 200; verify tree no longer shows user; keep `TEST_SHARE` untouched

**Success criteria:** Full create lifecycle passes via UI with backend and Samba verification, validation errors shown, no log errors.
