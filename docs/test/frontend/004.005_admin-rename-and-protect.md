# Test Case: 004.005_admin-rename-and-protect

## Test Objective

Verify admin rename via `PUT /useradmin` is allowed in the UI (`Username` editable with helper `Admin username can be changed` when `is_admin:true`) and that admin delete is protected (Delete button hidden or backend rejects `DELETE /user/{admin}` with 404/409), with cleanup reverting the rename.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Verify admin exists: `curl -s http://192.168.0.68:3000/api/users | jq -r '.[] | select(.is_admin==true) | .username'` → `ORIG_ADMIN` (typically `admin`); save `ORIG_ADMIN`; ensure `GET /users` contains exactly one admin (`map(select(.is_admin))|length==1`)
3. Ensure no existing collision: `TEST_ADMIN="adm$(date +%s | tail -c 5)"` (satisfies `^[a-zA-Z0-9 _-]+$`, ≤30); `curl -s http://192.168.0.68:3000/api/users | jq -r --arg u "$TEST_ADMIN" '.[] | select(.username==$u) | .username'` → empty; if present `DELETE /user/$TEST_ADMIN` first (regular user) or skip
4. Frontend at `http://localhost:3080/` → `Users` tab loads with `Administrators` group containing `ORIG_ADMIN` (`#mui-tree-view-2-$ORIG_ADMIN`); ensure `availableShares` non-empty for later share assignment check (optional)
5. Record baseline `pdbedit`: `docker exec app_local_sambanas2 pdbedit -L | grep -E "^$ORIG_ADMIN:"` → found

**If any step fails** (no admin, API unreachable), **skip**.

## Execution

1. Navigate `http://localhost:3080/` → `USERS` → expand `group-admin` → click `ORIG_ADMIN` `p` inside `#mui-tree-view-2-$ORIG_ADMIN > div > div > p` → details panel shows `Administrator` chip, `Edit User`/`Delete User` icons
2. Click `Edit User` → inline `UserEditForm` appears: verify `Username` input `#_r_*h_*` is **not** `readOnly` (admin can rename) with helper `Admin username can be changed` (vs regular `Username cannot be changed…`); `Password`/`Repeat Password` empty, RW/RO Autocompletes present
3. Change username: clear `Username` → type `$TEST_ADMIN`, change password: `NEW_ADMIN_PASS="Adm$(date +%s | tail -c 5)!"` into both password fields (`#_r_*i_*`, `#_r_*k_*`) with matching repeat; optionally add RW share `media` via `#_r_*m_-option-8` to also test share persist on admin rename
4. Submit `SAVE CHANGES` → verify network `PUT /useradmin` (not `PUT /user/{username}`) → 200 with body `{"username":"$TEST_ADMIN",...}`; toast `Admin $TEST_ADMIN updated successfully` (or `Admin $ORIG_ADMIN updated…` depending on implementation — accept either but body must contain `$TEST_ADMIN`)
5. Verify UI: tree now shows `$TEST_ADMIN` in `Administrators` with chip, old `ORIG_ADMIN` gone; chip counts updated; details panel shows new username and shares; `localStorage["users.selectedUserKey"]` updated if selection was preserved (check via inspect `localStorage.getItem`)
6. Verify backend: `curl -s http://192.168.0.68:3000/api/users | jq -r '.[] | select(.is_admin==true) | .username'` → `$TEST_ADMIN`; old name absent; `pdbedit -L | grep $TEST_ADMIN` → found, old gone; `smbclient -L //127.0.0.1 -U $TEST_ADMIN%$NEW_ADMIN_PASS` → OK (shares listed); old creds fail
7. Verify delete protection: with `$TEST_ADMIN` selected, check `Delete User` button state — expected hidden or disabled for admin (spec: admin cannot be deleted via `DELETE /user/{username}`); if visible, click `Delete` → confirm with acknowledgement → expect backend `DELETE /api/user/$TEST_ADMIN` → 404 or 409 with detail `User not found` or `cannot delete admin`, toast error, tree still shows admin (no deletion)
8. Negative rename collision: attempt to rename admin to an existing regular username (create `tmpuXXXX` via `POST /user` first), then `PUT /useradmin` with `username=tmpuXXXX` → expect 409 `already exists`; verify toast error and admin name unchanged

**Assertions:**
- Admin username field editable (vs regular locked), helper text correct, rename uses `PUT /useradmin` 200, Samba reflects new name/pass
- Delete protection holds (hidden/disabled or 404/409 on attempt)
- Duplicate rename 409 handled

## Validation

1. **Cleanup revert:** `PUT /useradmin` with `{"username":"$ORIG_ADMIN","password":"NewPass123!","rw_shares":[...]}` or original password restored from backup → 200; verify `GET /users` shows `ORIG_ADMIN` again, `pdbedit -L` shows `ORIG_ADMIN`, `$TEST_ADMIN` gone; delete temporary `tmpuXXXX` if created via `DELETE /user/tmpuXXXX` → 204
2. Logs: `ha addons logs local_sambanas2 | tail -30` and `ha core logs | tail -20` → no ERROR except expected 404/409 for protected delete; `testparm -s` still OK
3. Check no orphan Samba entries: `pdbedit -L | wc -l` equals baseline+admin only; `smbclient -L` with reverted creds works

**Success criteria:** Admin rename lifecycle via UI succeeds, delete blocked, duplicate rename rejected, Samba and backend consistent after revert, no log errors.
