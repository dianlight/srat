# Test Case: 001.012_share-actions-menu-ui

## Test Objective

Verify that the `ShareActions` overflow menu (small-screen `Menu` path) opens and closes correctly, exercising the MUI 9 `onClose` reason union (`backdropClick` | `escapeKeyDown` | `tabKeyDown`). This is a non-destructive regression case for the MUI 9.5 `onClose` type tightening — no share is modified or deleted.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Verify at least one share exists: `curl -s http://192.168.0.68:3000/api/shares | jq -r '.[].name'` — if none, create one via `001.001` preparation first
3. Ensure frontend is served at `http://localhost:3080/` (via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote`) — page loads with no JS errors
4. Record baseline: `GET /api/shares` count (must be unchanged at the end)

**If any preparation step fails** (no shares exist, UI not accessible), the test must be **skipped**.

## Execution

1. Navigate to `http://localhost:3080/` → click Shares tab (`#full-width-tab-2`)
2. Expand the group containing a share and select the share row so `ShareActions` renders
3. Resize the browser viewport to a small width (e.g. 500x800) so `ShareActions` renders the `more actions` (⋯) overflow button instead of inline icon buttons; take a fresh snapshot and confirm the `more actions` button is present
4. Click the `more actions` button → a `Menu` opens showing `View Volume Mount Settings` and the enable/disable/delete item; assert both menu items are visible and browser console shows no new errors
5. Press `Escape` → the menu must close (no `[role=menu]` remains in the DOM after the exit transition); assert console still shows no new errors
6. Click the `more actions` button again to reopen the menu → press `Tab` to move focus; if the menu closes with reason `tabKeyDown`, assert it closes cleanly with no console errors (if focus simply moves within the open menu, that is also acceptable — record which behavior was observed)
7. Click elsewhere on the page (backdrop click) with the menu open → assert the menu closes with no console errors
8. Restore the viewport to desktop width (e.g. 1280x900) and confirm the inline action buttons render again

**Assertions:**

- Overflow `Menu` opens on `more actions` click with the expected items
- `Escape`, `Tab`, and backdrop click all dismiss the menu without console errors or a stuck open menu
- No network mutation occurs (`GET /api/shares` count equals baseline; no `PUT`/`POST`/`DELETE` issued)
- TypeScript compiles cleanly (`bunx --bun tsc --noEmit` in `frontend/`), proving the `onClose` handler accepts the full MUI 9 reason union

## Validation

1. Verify share count unchanged: `curl -s http://192.168.0.68:3000/api/shares` length equals baseline
2. Check addon logs: `ha addons logs local_sambanas2 --lines 15` — no `ERROR`/`FATAL`/`panic` introduced by this test (pre-existing periodic SMART `WARN` lines are expected noise)
3. Check browser console messages accumulated during the run contain no uncaught errors attributable to the menu open/close window

**Success criteria:** Menu opens and dismisses via all three reasons with zero console errors, zero API mutations, clean `tsc`, and no new addon log errors.
