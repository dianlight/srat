# Test Case: 003.012_ha-mount-actions-and-per-mount-entry-actions

## Test Objective

Verify that the Volumes UI correctly shows mount/unmount/disable/enable actions for HA-managed and regular partitions, including per-mount-entry actions when multiple mount paths exist, and that Create Share / Go to Share are always available for HA-managed partitions.

## Preparation

1. Ensure the SRAT addon is running and the frontend dev server is reachable at `http://localhost:3080/`
2. Confirm at least one HA-managed partition exists (`is_ha_mounted: true` in `GET /api/volumes`)
3. Open the Volumes tab in the browser and locate a partition row
4. Have a non-HA partition (SRAT-managed, under `/mnt/`) also available for comparison

**If any preparation step fails**, the test must be **skipped**.

## Execution

### Part A: HA-Managed Partition Actions

1. Locate a partition row whose `is_ha_mounted` is true
2. Verify the "Managed by Home Assistant" badge is visible for that partition
3. Assert that:
   - **Mount button is NOT visible** (or disabled with tooltip: "Home Assistant manages mount lifecycle")
   - **Automount toggle is NOT visible** for that partition
   - **Format / Check / Set Label actions are NOT visible** for that partition
   - **Unmount action is NOT visible** for that partition
   - **Create Share and Go to Share ARE still available** (these are the only supported actions for HA-mounted disks)
4. Open the partition's details panel (via the row or tree view) and verify the badge and action availability persists

### Part B: Per-Mount-Entry Actions (multiple mount paths on same partition)

1. Locate a partition that has **multiple mount paths** (e.g., HA mount `/media/ha_usbtest` AND SRAT mount `/mnt/usbtest`)
2. Verify that per-mount-entry actions are shown for each mount entry
3. Assert that:
   - The partition row shows a badge indicating multiple mount points
   - For each mount entry, the appropriate actions are visible (Mount / Unmount / Automount / Create Share depending on mount state)
   - Create Share / Go to Share are available for each mount entry
   - No `null` action set is returned for the partition (actions should not be suppressed due to multiple entries alone)
4. If the partition has one HA-managed mount and one SRAT mount, verify that the HA mount shows only Create Share / Go to Share actions, while the SRAT mount shows the full set of applicable actions

### Part C: Duplicate Name 409 Validation (from 003.020 context)

1. Attempt to create a second share with the same name on the HA-managed partition
2. Verify that a 409 Conflict error is surfaced inline (toast, error banner, or field-level message)
3. Assert the error message clearly indicates the conflict reason ("Share name already exists")

**Assertions:**

- HA-managed rows: badge shown, mount/automount/format/check/unmount hidden, Create Share / Go to Share visible
- Multi-mount partitions: per-entry actions shown correctly; Create Share available on each entry
- Duplicate name: 409 Conflict surfaced inline with actionable error message

**Success criteria:** HA-managed and multi-mount partition actions are correctly displayed; 409 conflicts are visible to the user; no unexpected `null` action sets.
