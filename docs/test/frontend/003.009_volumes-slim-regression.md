# Test Case: 003.009_volumes-slim-regression

## Test Objective

Verify the Volumes slim refactor (issue 1235) causes no UI regression: Volumes tree renders, volume/partition selection works via `useVolumeSelection`, mount/unmount works via `useMountVolume` dialog, SMART panel and partition details render, and no console errors appear.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` — state should be `started`
2. Verify addon API is reachable: `curl -s http://192.168.0.68:3000/api/health` — should return 200
3. Verify volumes API returns data: `curl -s http://192.168.0.68:3000/api/volumes` — should return 200 with disk list
4. Ensure frontend is served at `http://localhost:3080/` (via `mise run //frontend:dev:remote`) — page should load with no JS errors
5. Note branch under test: `issue-1235-artful-narwhal` (Volumes.tsx slim + `useMountVolume` + `useVolumeSelection` + `utils.ts` + `SmartStatusPanel`/`VolumesTreeView` changes)

**If any preparation step fails** (addon not running, API unreachable, volumes endpoint 500), the test must be **skipped**.

## Execution

1. Navigate to `http://localhost:3080/`, click Volumes tab, wait for tree to resolve (no infinite "Loading volumes...")
2. Assert tree renders: disk nodes + partition children visible; select a partition — `VolumeDetailsPanel` / `PartitionInformationCard` updates (selection hook)
3. Assert SMART panel renders for a SMART-capable disk (`SmartStatusPanel` — no crash on missing attributes, graceful empty/error state otherwise); take screenshot
4. Mount flow (if an unmounted mountable partition exists): open `VolumeMountDialog` via tree/MOUNT action, confirm mount — assert `is_mounted:true` in UI without reload and `GET /api/volumes` agrees
5. Unmount flow (if a mounted data partition exists, prefers WD PC SN740 -part2 if present): UNMOUNT — assert UI reflects unmounted, cleanup remounts
6. Check browser console: no uncaught errors, no failed `GET /api/volumes` (2xx only)

**Assertions:**

- Volumes page loads without red error banner
- Tree selection updates details panel (fail if selection stale/empty → `useVolumeSelection` regression)
- Mount/unmount succeeds and persists via API (fail if dialog error → `useMountVolume` regression)
- `SmartStatusPanel` renders or degrades gracefully (fail on crash/blank panel exception)
- Console has no uncaught errors from `Volumes.tsx`/`utils.ts`/`diskIcon`/`decodeEscapeSequence` changes
- Network: `GET /api/volumes` returns 200

## Validation

1. Re-fetch volumes after mount/unmount actions and compare with UI state (mandatory freshness check — if tree label/mount state differs from `GET /filesystem/label` or mount state, restart addon to clear cache and re-verify before filing bug)
2. Check addon logs: `ha addons logs local_sambanas2 --lines 50` — no `ERROR`/`panic` introduced by navigation
3. Verify WebSocket indicator stays green/connected after Volumes navigation
4. Clean up: remount any unmounted test partition, restore original mount state, leave labels unchanged

**Success criteria:** Tree + selection + mount + SMART details all work as before the slim refactor; no console/API/log errors; state mutations are consistent across endpoints after cache-aware re-check.
