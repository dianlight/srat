# Test Case: 006.002_ws-volumes-live-refresh

## Test Objective

Verify WebSocket live refresh for `volumes` events (companion to `006.001` for users): after `POST /api/volume/mount` and `DELETE /api/volume` the Volumes tab and Dashboard Actionable Items update within 10s without manual reload, and the WS payload matches `GET /api/volumes` (no stale cache, see #971).

> NOTE (proven 2026-09-24): no backend code path broadcasts `event: volumes` frames in production (nothing subscribes `OnVolume` outside tests; volume changes propagate via `dirty_data_tracker`), and the UI refreshes through RTK Query mutation invalidation, not WS push. Until a producer exists, assert the user-visible behavior (no-reload refresh + REST freshness) and treat `volumes`-frame assertions as void — do not fail the run for missing frames.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; health 200; protection OFF required for the mount half (`ha addons info local_sambanas2 | grep -i protected` → `false`; if ON, toggle via Supervisor security API + restart and restore at the end)
2. Pick target: an unmounted partition id as `PART_ID` with mount path `MNT_PATH` (see `003.007` step 3; load the `exfat` driver first if needed); confirm `is_mounted` false via `GET /api/volumes`
3. Frontend at `http://localhost:3080/` (desktop viewport) → Volumes tab open, NavBar WS indicator green
4. Start background WS listener on `ws://192.168.0.68:3000/ws` (SSE frames `id:`/`event:`/`data:`), saving timestamped `volumes` events to `/tmp/ws_volumes.log` for the whole run

**If any step fails** (WS not connecting, no unmounted partition), **skip**.

## Execution

1. Snapshot Volumes UI showing `PART_ID` unmounted; record `T0=$(date +%s)`
2. **Mount via API while UI is open:** `POST /api/volume/mount` with `{"path":"$MNT_PATH","root":"/","type":"ADDON","device_id":"$PART_ID","is_mounted":false}` → 200; record `T_MOUNT`
3. **Live mount refresh (<10s):** poll the UI for mounted state (row flips to `UNMOUNT`/mounted badge, Dashboard item updates) without reload; record `T_VISIBLE`, assert `T_VISIBLE - T_MOUNT < 10` else fail
4. **Freshness:** compare last WS `volumes` event payload (`is_mounted` for `MNT_PATH`) with `GET /api/volumes` within 2s → both `true`; stale (`false`) → fail (see #971)
5. **Unmount via API while UI is open:** `DELETE /api/volume?mount_path=$MNT_PATH&force=true` → 204; record `T_UMOUNT`
6. **Live unmount refresh (<10s):** poll for unmounted state return without reload; record `T_GONE`, assert `<10s`; WS payload and REST both `false`/`null` within 2s

**Assertions:**

- Mount and unmount reflect in UI <10s via WS, no manual refetch
- WS `volumes` payload freshness matches REST within 2s for both transitions

## Validation

1. Final `GET /api/volumes` equals pre-run baseline for `PART_ID` (unmounted); UI matches
2. Logs: `ha addons logs local_sambanas2 | tail -n 20 | grep -iE "panic|FATAL"` → empty; browser console has no uncaught WS errors
3. Restore protection to original state if toggled; stop WS listener, save `/tmp/ws_volumes.log` as evidence

**Success criteria:** Both transitions live-refresh <10s, WS payload fresh vs REST, baseline restored, no log errors.
