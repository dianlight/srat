# Test Case: 001.012_ntfs-share-ui-force-user

## Test Objective

Verify the srat#1391 fix through the UI path: creating a share on an NTFS mount via the Shares UI produces an `smb.conf` section without `force user`/`force group`, while an ext4-backed share keeps them.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `state: started`; `curl -s http://192.168.0.68:3000/api/health` → 200 with `alive:true`
2. Frontend dev server running at `http://localhost:3080/` with `API_URL=http://192.168.0.68:3000/` baked (verify per `test-remote-environment` Step 5 Phase-0 check).
3. An NTFS partition is mounted (`GET /api/volumes` → `fstype` `ntfs3` or alias, `is_mounted:true`). Reuse `SRATNTFS01` if present. Record its mount path as `MNT_PATH`.
4. No existing share on `MNT_PATH` (`share == null` in `GET /api/volumes`). Delete any leftover test share first.
5. Save pristine settings: `GET /api/settings` → `ORIG.json` (restore exclusively from it if needed — `PUT /api/settings` replaces the whole object).

**If any preparation step fails** (addon not running, no mounted NTFS volume, frontend not reachable), the test must be **skipped**.

## Execution

1. Open `http://localhost:3080/` → Shares tab. Screenshot to confirm the page loaded with no red error banners.
2. Create a share via the UI wizard: name `ntfs-ui-<timestamp>`, volume `MNT_PATH`, usage `media`. Submit and wait for the success indication (~5–10 s for async `RESTART` soft restart).
3. Verify via API: `GET /api/shares` includes the new share with `mount_point_data.fstype` `ntfs3` (or alias).
4. Inspect `smb.conf`: `docker exec app_local_sambanas2 sh -c 'sed -n "/^\\[NTFS_UI_<TIMESTAMP>\\]/,/^$/p" /etc/samba/smb.conf'` → NO `force user` / `force group` lines in the NTFS section. DEBUG line shows `"fs":"ntfs3"` with no `force_user`/`force_group` keys.
5. Negative control: an ext4-backed share section STILL contains `force user = root` / `force group = root`.

**Assertions:**

- UI share creation succeeds with no console errors and 2xx network responses
- NTFS share section has no `force user`/`force group` lines
- Ext4 share section keeps `force user = root` / `force group = root`
- WebSocket status indicator in the NavBar stays green

## Validation

1. Browser console (`browser_console_messages` for the case time window only) → no new uncaught errors; transient WS-handshake noise during restart is expected and ignored.
2. Logs: `ha addons logs local_sambanas2` tail → no `ERROR/panic` for share/config; `ha core logs` → no `custom_components.srat` tracebacks.
3. Cleanup: delete the test share via UI or `DELETE /api/share/<name>` → 204; verify `GET /api/shares` no longer contains it and the `smb.conf` section is removed after ~5 s. Record deviations in evidence.

**Success criteria:** UI-created NTFS share omits force-user lines while ext4 keeps them; console and logs clean; cleanup complete.
