# Test Case: 007.010_alert-toggle-off-stale-dismissal

## Test Objective

Verify that switching the `alert_custom_component` toggle OFF (with lab mode ON) dismisses a live `custom_component_missing` problem without a restart or manual DELETE, and that switching it back ON re-raises the problem on the next status sync. Covers the stale-dismissal hook in `PUT /api/settings` (found during the 007.006 remote run: toggling lab OFF left the row behind until an unrelated sync).

## Preparation

1. Ensure the SRAT addon is running: `ha apps info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Record baselines: `GET /api/settings` → note `experimental_lab_mode`, `alert_custom_component`; `GET /api/problems` → note keys
3. Enable lab mode (if OFF): `PUT /api/settings` with `experimental_lab_mode: true` → 200
4. Raise the problem: `GET /api/settings/homeassistant/custom-component/status` (expect 200 with lab on) → `GET /api/problems` contains `custom_component_missing`
5. If the problem does not appear (component installed or connected), the test must be **skipped**

**If any preparation step fails** (addon not running, API unreachable), the test must be **skipped**.

## Execution

1. `PUT /api/settings` with `alert_custom_component: false` (keep lab ON) → assert 200
2. Assert stale dismissal: `GET /api/problems` no longer contains `custom_component_missing` (no restart, no explicit DELETE)
3. Restart the addon, wait 12 s → assert the key is still absent (suppressed at source, not just deleted)
4. `PUT /api/settings` with `alert_custom_component: true` → `GET /api/settings/homeassistant/custom-component/status` → assert `custom_component_missing` is back with `ignored: false`
5. Restore baseline toggle values → Apply

**Assertions:**

- Toggle OFF dismisses the live problem via the settings-save hook alone
- Suppression survives a restart (no re-emit while disabled)
- Toggle ON re-raises through the normal sync path
- No `panic`/`FATAL` in addon logs after each step

## Validation

1. Check addon logs: `ha apps logs local_sambanas2 | tail -n 30 | grep -iE "panic|FATAL"` → empty
2. Confirm `GET /api/settings` matches the recorded baseline for `experimental_lab_mode` and `alert_custom_component`
3. Confirm addon state `started` and health 200

**Success criteria:** Alert-toggle OFF cleans up stale custom-component problems immediately and durably; toggle ON restores emission; baseline restored.
