# Test Case: 002.001_check-disk-health

## Test Objective

Verify that disk health can be checked and reported correctly through the SRAT API, including SMART monitoring for attached disks.

## Preparation

1. Ensure the SRAT addon is running: `addon ls` - should show srat addon as `running`
2. Verify disks are detected: `df -h` - should show at least one mounted volume under `/mnt/`
3. Check disk health status: `curl -s http://localhost:8090/api/disks | jq '.'` - should return disk information
4. Verify SMART monitoring is available: `curl -s http://localhost:8090/api/disks/smart | jq '.'` - should return SMART data if available
5. Set up test environment variables:
   ```bash
   export SRAT_TEST_MODE=true
   ```

**If any preparation step fails** (addon not running, no disks detected, API unreachable), the test must be **skipped**.

## Execution

1. Check disk health via API:
   ```bash
   curl -s http://localhost:8090/api/disks
   ```
2. Verify response contains disk list with status fields
3. For each disk, check SMART data:
   ```bash
   curl -s http://localhost:8090/api/disks/smart
   ```
4. Verify SMART attributes are present and readable

**Assertions:**
- API returns HTTP 200
- Response contains disk list with expected fields (name, model, status)
- SMART data includes temperature, read error rate, and other key attributes for each disk

## Validation

1. Verify disk health is displayed in the SRAT frontend UI at `http://localhost:8090/disks`
2. Confirm SMART attributes are shown correctly for each disk
3. Run integration test to verify disk status matches actual hardware state
4. Test that disk health updates when disks are added/removed

**Success criteria:** All assertions pass and disk health information is accurate and can be updated.
