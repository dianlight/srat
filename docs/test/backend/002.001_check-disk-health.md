# Test Case: 002.001_check-disk-health

## Test Objective

Verify that disk health can be checked and reported correctly through the SRAT API, including partition mount state and SMART-capable disks via the volumes endpoint.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Verify disks are detected: `curl -s http://192.168.0.68:3000/api/volumes | jq '.'` → should return JSON array with at least one disk and its partitions (`df -h` should show at least one mounted volume under `/mnt/`)
3. Check disk health status via volumes: `curl -s http://192.168.0.68:3000/api/volumes | jq '.[].partitions'`—should return partition map with mount metadata
4. Verify SMART/capabilities are reported: `curl -s http://192.168.0.68:3000/api/capabilities | jq '.'`—check `lib_smart_available` field; if `false`, SMART assertions are skipped
5. Set up test environment variables:
   ```bash
   export SRAT_TEST_MODE=true
   ```

**If any preparation step fails** (addon not running, no disks detected, API unreachable), the test must be **skipped**.

## Execution

1. Fetch volumes health via API:
   ```bash
   curl -s http://192.168.0.68:3000/api/volumes | jq '.'
   ```
2. Verify response contains disk list with partition and mount fields (`id`, `partitions`, `mount_point_data.is_mounted`)
3. For each disk, verify partition mount state is readable:
   ```bash
   curl -s http://192.168.0.68:3000/api/volumes | jq '.[] | {id, partitions: (.partitions | keys)}'
   ```
4. If SMART is available (`/api/capabilities` → `lib_smart_available:true`), verify disks report SMART-relevant attributes via frontend `DiskHealthMetrics` or volume details

**Assertions:**

- API `GET /api/volumes` returns HTTP 200
- Response contains at least one disk with expected fields (id, partitions)
- Each partition's `mount_point_data` reflects correct `is_mounted` state
- When SMART is available, health attributes are present and readable

## Validation

1. Verify disk health is displayed in the SRAT frontend UI at `http://localhost:3080/` → Dashboard → DiskHealthMetrics (served via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote`)
2. Confirm partition mount states shown in Volumes tab match `GET /api/volumes`
3. Run integration check to verify disk status matches actual hardware state (`lsblk` on host)
4. Test that volume list updates consistently between REST and WS (`ws://192.168.0.68:3000/ws` event `volumes`)

**Success criteria:** All assertions pass and disk health information is accurate and consistent across API, WS, and UI.
