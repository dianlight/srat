# Test Case: 001.001_create-a-share

## Test Objective

Verify that a new SMB share can be created successfully via the SRAT API and that the share configuration is properly rendered in `smb.conf`.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` - state `started`; `curl -s http://192.168.0.68:3000/api/health` - 200
2. Verify a data disk is mounted and accessible: `df -h` - should show at least one mounted volume under `/mnt/`
3. Check existing shares configuration: `testparm -s /etc/samba/smb.conf` - note current share count
4. **Select a free mount point** (critical—avoid 422 `Invalid share configuration` when reusing an already-shared path):
   ```bash
   # Find a mounted partition with share==null (e.g. ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2)
   curl -s http://192.168.0.68:3000/api/volumes | jq '.[] | select(.id=="ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056") | .partitions["ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2"] | .mount_point_data | to_entries[0].value | {path,device_id,is_mounted,share}'
   # Expect share:null and is_mounted:true; otherwise pick another part where share==null
   # Save full mount object for creation payload:
   MNT=$(curl -s http://192.168.0.68:3000/api/volumes | jq -c '.[] | select(.id=="ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056") | .partitions["ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2"].mount_point_data | to_entries[0].value')
   ```
5. Set up test environment variables:
   ```bash
   export SRAT_TEST_MODE=true
   export TEST_SHARE_NAME="test-share-$(date +%s)"
   ```
6. Verify API endpoint is accessible: `curl -s http://192.168.0.68:3000/api/shares | jq '.'` - should return JSON array

**If any preparation step fails**, the test must be **skipped** and documented in test logs.

## Execution

1. Create a new share via API (use the `MNT` object from preparation—do not craft a dummy path):
   ```bash
   PAYLOAD=$(echo "$MNT" | jq --arg n "$TEST_SHARE_NAME" '{name:$n, mount_point_data:., usage:"media", guest_ok:true, timemachine:false}')
   curl -X POST http://192.168.0.68:3000/api/share \
     -H "Content-Type: application/json" \
     -d "$PAYLOAD" -w "\nHTTP:%{http_code}\n"
   ```
2. Verify API response returns HTTP 201 Created
3. Verify share was created in Samba config (allow ~5-10 s for async `RESTART` soft restart):
   ```bash
   sleep 5; ssh root@192.168.0.68 "docker exec app_local_sambanas2 testparm -s 2>&1 | grep -i -A5 \"${TEST_SHARE_NAME}\""
   # section is uppercased: [TEST-SHARE-...]; use -i
   ```
4. Verify `smb.conf` contains the new share entry with `path = /mnt/...` matching `MNT.path`

**Assertions:**

- API returns status code 201
- `smb.conf` contains new share with correct path (case-insensitive match)
- Share appears in share listing: `curl -s http://192.168.0.68:3000/api/shares | jq -r ".[].name"` includes `${TEST_SHARE_NAME}`

## Validation

1. Verify share is listed in the SRAT frontend UI at `http://localhost:3080/` → Shares tab (group `Media Shares` should grow by 1)
2. Confirm share properties match what was created:
   - Share name matches `TEST_SHARE_NAME`
   - Share path matches `MNT.path` (e.g. `/mnt/ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056-part2`)
   - `guest_ok:true`, `usage:media` as sent
3. Run integration test to verify share is accessible via Samba client (if guest_ok): `smbclient -L //192.168.0.68 -U guest%`
4. Clean up: remove test share via API `DELETE http://192.168.0.68:3000/api/share/${TEST_SHARE_NAME}` → 204; verify `GET /api/shares` no longer contains it and `testparm -s` section removed after ~5 s

**Success criteria:** All assertions pass and share is confirmed created and then cleaned up.
