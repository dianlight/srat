# Test Case: 004.002_remove-admin-default-shares

## Test Objective

Replicate hassio-addons#759: removing default shares from the admin user via edit must persist. Verify PUT /useradmin with emptied `rw_shares`/`ro_shares` clears assignments and survives restart.

## Preparation

1. Ensure addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Capture baseline admin: `curl -s http://192.168.0.68:3000/api/users | jq '.[] | select(.is_admin)'` → note `username`, `rw_shares`, `ro_shares` (expect non-empty defaults)
3. Capture shares list: `curl -s http://192.168.0.68:3000/api/shares | jq -r '.[].name'` → `SHARE_A` (at least one default share assigned to admin)
4. Record target: pick one default share assigned to admin to remove (e.g. first entry of `rw_shares`)

**If any preparation step fails** (no admin, no shares assigned), **skip** and document.

## Execution

1. Remove one share from admin via API (keep password empty to keep existing):
   ```bash
   ADMIN=$(curl -s http://192.168.0.68:3000/api/users | jq -r '.[] | select(.is_admin) | .username')
   CUR_RW=$(curl -s http://192.168.0.68:3000/api/users | jq -c --arg u "$ADMIN" '.[] | select(.username==$u) | .rw_shares // []')
   NEW_RW=$(echo "$CUR_RW" | jq -c '.[1:]')
   curl -s -w "\n%{http_code}\n" -X PUT http://192.168.0.68:3000/api/useradmin \
     -H "Content-Type: application/json" \
     -d "{\"username\":\"$ADMIN\",\"rw_shares\":$NEW_RW,\"ro_shares\":[]}"
   # expect 200
   ```
2. Verify GET reflects removal: `curl -s http://192.168.0.68:3000/api/users | jq --arg u "$ADMIN" '.[] | select(.username==$u) | {rw_shares,ro_shares}'` → removed share absent
3. Remove ALL shares: `PUT /useradmin` with `{"username":"$ADMIN","rw_shares":[],"ro_shares":[]}` → 200; GET must show empty arrays
4. Restart addon (`ha addons restart local_sambanas2`, wait 10 s) and re-GET admin → shares must stay empty

**Assertions:**

- PUT returns 200 for partial and full removal
- GET after PUT shows removal (no stale shares)
- Removal survives addon restart (replicates issue #759 symptom: "shares remain there")

## Validation

1. Check `smb.conf`: `docker exec addon_local_sambanas2 testparm -s` → no errors; admin share assignments consistent
2. Check logs: `ha addons logs local_sambanas2 | tail -30 | grep -iE "ERROR|panic"` → none new
3. Restore baseline: PUT back original `rw_shares`/`ro_shares` so later tests are unaffected
4. Verdict: if step 2 or 4 shows stale shares → **FAIL (issue confirmed)**; file/link srat issue referencing hassio-addons#759

**Success criteria:** Admin share removal persists across GET and restart; failure confirms the bug.
