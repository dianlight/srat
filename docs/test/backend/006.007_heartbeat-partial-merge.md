
# Test Case: 006.007_heartbeat-partial-merge

## Test Objective

Verify that `heartbeat` WebSocket frames do not clear unrelated coordinator state in the custom component: the coordinator `_on_heartbeat` handler merges only present keys, so `samba_status`, `process_status`, and `disk_health` sensor entities retain their values across heartbeats even when a frame omits (or nulls) some of those keys. Covers `custom_components/srat/coordinator.py` merge semantics.

## Preparation

1. Ensure the SRAT addon is running and health 200; ensure the custom component is deployed and HA core has no `custom_components.srat` errors in core logs
2. Verify the referenced entities exist and are not `unknown`: `sensor.srat_samba_process_status` and `sensor.srat_global_disk_health` (HA states API) → both have concrete states
3. Open a WebSocket listener in the background (RFC6455 handshake **with an `Origin` header**): `python3 docs/test/ws_listen.py /tmp/srat_hb.log 120 & echo $! > /tmp/srat_hb.pid`; wait 5 s and confirm `heartbeat` frames arrive in `/tmp/srat_hb.log`
4. Record baseline states of `sensor.srat_samba_process_status` and `sensor.srat_global_disk_health`

**If any preparation step fails** (WS unreachable, no heartbeat frames within 15 s, entities `unknown`), the test must be **skipped**.

## Execution

1. Let ≥3 heartbeat frames accumulate (~30–60 s); extract each frame's JSON key set: `grep -o '"event": "heartbeat"' /tmp/srat_hb.log` then inspect `data:` payloads for presence/absence of `samba_status`, `samba_process_status`, `disk_health`
2. After each observed heartbeat, re-read `sensor.srat_samba_process_status` and `sensor.srat_global_disk_health` states
3. Trigger state churn to prove merge-vs-overwrite: `PUT /api/settings` toggling `log_level` (e.g. `debug` → back to baseline) to force activity, then re-read both sensor states after ≥1 heartbeat
4. Note in evidence whether any frame omitted a key (partial frame) — if all frames carry all three keys, record that partial-merge behavior was not observable live and is covered only by unit tests (deviation, not failure)

**Assertions:**

- Sensor states never flip to `unknown`/`None` while heartbeats are flowing (a partial frame must not wipe a present key — old behavior would clear all three keys from a `data` dict lacking them)
- No new `custom_components.srat.coordinator` errors/tracebacks in HA core logs during the window

## Validation

1. Kill the listener: `kill $(cat /tmp/srat_hb.pid)`
2. Restore baseline settings if step 3 changed them; confirm `GET /api/settings` matches baseline
3. HA core logs: no `Traceback` or `ERROR` from `custom_components.srat`; addon logs clean (`panic|FATAL` → empty)

**Success criteria:** heartbeats flow continuously, both sensors retain stable states throughout (merge semantics hold), logs clean, baseline restored.
