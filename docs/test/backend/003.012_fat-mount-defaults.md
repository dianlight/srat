# Test Case: 003.012_fat-mount-defaults

## Test Objective

Verify FAT-family (exFAT/vfat) mount defaults for issue #1264: mounting an exFAT or FAT32 partition with empty flags applies adapter-declared `uid`/`gid`/`umask` defaults so the volume is readable/writable through Samba instead of root-locked.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `state: started`; `curl -s http://192.168.0.68:3000/api/health` → 200 with `alive:true`
2. Target partition (may require format — confirm with user first): pick a spare data partition (`system:false`) and export `TEST_PARTITION_ID` and `TEST_FSTYPE` (`exfat` or `vfat`). If none exists in the wanted fstype, format the agreed spare:
   ```bash
   curl -s -X POST http://192.168.0.68:3000/api/filesystem/format -H "Content-Type: application/json" -d "{\"partitionId\":\"$TEST_PARTITION_ID\",\"fstype\":\"$TEST_FSTYPE\",\"label\":\"SRATFAT01\",\"force\":false,\"verbose\":true}"
   ```
   Poll `GET /filesystem/state?partition_id=$TEST_PARTITION_ID` up to 120s → `isClean:true`.
3. Ensure partition is unmounted before mount test (via UI UNMOUNT or `DELETE /api/volume?mount_path=<path>`). If a share is attached (`share != null`), delete it first.

**If any preparation step fails** (no agreed spare partition, user declines format, addon not running), the test must be **skipped**.

## Execution

1. Mount with empty flags (defaults path): `POST /api/volume/mount` with `mountPointData` for `$TEST_PARTITION_ID` and empty `flags`/`custom_flags` → 200, `is_mounted:true`.
2. Verify default flags applied at OS level: `docker exec app_local_sambanas2 sh -c 'cat /proc/mounts | grep $TEST_PARTITION_ID'` → mount options include `uid=0,gid=0` (or equivalent) and an open `umask`/`fmask,dmask` per the adapter defaults.
3. Verify API reflects defaults: `GET /api/volumes | jq --arg pid "$TEST_PARTITION_ID" '.[] | select(.partitions[$pid]!=null) | .partitions[$pid].mount_point_data | to_entries[0].value | {fstype, custom_flags}'` → `fstype` matches `$TEST_FSTYPE`, flags coherent with mount options.
4. Unmount to restore baseline: `DELETE /api/volume?mount_path=<path>&force=true` → 204 → `is_mounted:false` in `GET /api/volumes`.

**Assertions:**

- Mount with empty flags succeeds and OS mount options carry `uid`/`gid`/`umask` defaults
- `GET /api/volumes` agrees with `/proc/mounts` on fstype and mount state
- Unmount restores the unmounted baseline

## Validation

1. Write smoke while mounted (direct FS, before step 4): `docker exec app_local_sambanas2 sh -c "echo hello > /mnt/$TEST_PARTITION_ID/.srat_fat_test && cat /mnt/$TEST_PARTITION_ID/.srat_fat_test && rm /mnt/$TEST_PARTITION_ID/.srat_fat_test"` → `hello` with no I/O error.
2. Logs: `ha addons logs local_sambanas2` tail → no `ERROR/panic` for format/mount/unmount; `ha core logs` → no `custom_components.srat` tracebacks.
3. Restore pre-test mount state (mounted vs unmounted) and record final state in evidence.

**Success criteria:** FAT defaults applied on mount; write smoke passes; mount/unmount lifecycle clean; logs clean.
