# Test Case: 006.003_ws-problem-events

## Test Objective

Verify problem lifecycle events stream over the WebSocket (`ws://192.168.0.68:3000/ws`, SSE frames `id:`/`event:`/`data:`): ignoring, re-enabling, and dismissing the `protected_mode` problem each emit a corresponding problem event promptly, so dashboard toasts and lists update without polling.

## Preparation

1. Ensure the SRAT addon is running: `ha apps info local_sambanas2` → `started`; health 200
2. Verify WS is reachable: `curl -H "Connection: Upgrade" -H "Upgrade: websocket" http://192.168.0.68:3000/ws -v` → expect SSE frames (`id:`/`event:`/`data:`), not an HTTP error page
3. Ensure protection mode is ON and `protected_mode` problem is active with `ignored: false` (re-enable via `PUT /api/problems/protected_mode` if needed)
4. Open an SSE listener in the background before mutating state, e.g.: `curl -s -N http://192.168.0.68:3000/ws -H "Accept: text/event-stream" -o /tmp/srat_ws.log & echo $! > /tmp/srat_ws.pid`; wait 5 s and confirm `hello`/`heartbeat` frames arrive
5. Record baseline problem state: `GET /api/problems/protected_mode` → note `ignored`, `status`, `repeating`

**If any preparation step fails** (WS unreachable, no active problem), the test must be **skipped**.

## Execution

1. Ignore: `PUT /api/problems/protected_mode` with full body + `ignored: true, status: ignored` → 200; within 10 s assert `/tmp/srat_ws.log` contains a problem event for `protected_mode` with ignored status
2. Re-enable: `PUT` with `ignored: false, status: created` → 200; within 10 s assert a problem event showing `ignored: false`
3. Dismiss: `PUT /api/settings` with `alert_protected_mode: false` → 200; within 10 s assert a problem REMOVE/deleted event (or the key disappearing from the next `GET /api/problems`)
4. Re-arm: `PUT /api/settings` with `alert_protected_mode: true` → assert the problem reappears (`ignored: false`) and an event is emitted
5. Kill the listener: `kill $(cat /tmp/srat_ws.pid)`; restore baseline settings

**Assertions:**

- Each mutation (ignore / re-enable / dismiss / re-arm) produces a matching problem event within 10 s
- Event payloads carry the current `ignored`/`status` (no stale flags)
- No `panic`/`FATAL` in addon logs

## Validation

1. `GET /api/problems/protected_mode` → baseline state (`ignored: false`)
2. `GET /api/settings` → `alert_protected_mode: true` (baseline)
3. Check addon logs: `ha apps logs local_sambanas2 | tail -n 30 | grep -iE "panic|FATAL"` → empty
4. Confirm addon state `started` and health 200; listener process reaped

**Success criteria:** Full problem lifecycle is observable over WS with fresh payloads; baseline restored; logs clean.
