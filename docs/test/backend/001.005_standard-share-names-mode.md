# Test Case: 001.005_standard-share-names-mode

## Test Objective

Verify internal standard shares follow Settings `standard_share_names` mode (fixed by #1145, issue #1142): `GET /api/shares` lists all four names but annotates mode-hidden ones with `status.is_hidden:true` (`old` hides `local_apps`/`app_configs`, `new` hides `addons`/`addon_configs`, `both` hides nothing), while generated smb.conf contains only mode-visible shares. Legacy names must resolve to the new application directories (`/local_apps`, `/app_configs`).

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Baseline: `curl -s http://192.168.0.68:3000/api/settings | jq -r .standard_share_names` → record ORIG (expected `both`); save full ORIG JSON for cleanup
3. Verify all four internal shares exist in `both` mode: `curl -s http://192.168.0.68:3000/api/shares | jq -r '.[].name'` includes `addons`, `addon_configs`, `local_apps`, `app_configs` each with `usage:internal`
4. Clear the disabled-flag confounder: any of the four with `disabled:true` is omitted from smb.conf regardless of mode — enable each via `PUT /api/share/<name>/enable` → 200 before the matrix, and re-disable the same ones in cleanup (baseline has `addons` + `app_configs` disabled)
5. Test user: create `srat-int-$TS` via `POST /api/user` and assign to shares (see Execution step 4)

**If any preparation step fails** (health not 200, settings 404), **skip**.

## Execution

1. **Mode `old`:** `PUT /api/settings` with `standard_share_names:"old"` (merge into ORIG) → 200; wait ~10s for Samba soft restart; `GET /api/shares` must still list all four but `status.is_hidden` is `true` for `local_apps` + `app_configs` and `false`/absent for `addons` + `addon_configs`; `testparm -s` inside addon container shows `[addons]` / `[addon_configs]` sections with `path = /local_apps` and `path = /app_configs`, no `[local_apps]` / `[app_configs]` sections
2. **Mode `new`:** `PUT /api/settings` with `standard_share_names:"new"` → 200; wait ~10s; `GET /api/shares` must show `is_hidden:true` on `addons` + `addon_configs` and visible `local_apps` + `app_configs`; `testparm -s` shows only `[local_apps]` / `[app_configs]`
3. **Mode `both`:** `PUT /api/settings` with `standard_share_names:"both"` → 200; wait ~10s; `GET /api/shares` must show all four with no `is_hidden:true`; `testparm -s` shows all four sections, legacy paths rewritten to `/local_apps` and `/app_configs`
4. **User access:** create test user `POST /api/user {"username":"srat-int-<ts>","password":"<secret>"}` → 201; assign to one legacy-visible and one new-visible share per current mode (or verify via `smbclient -L //192.168.0.68 -U user%pass` that only mode-visible standard shares are enumerated + `smbclient //192.168.0.68/<share> -U user%pass -c "ls"` succeeds on a visible one)

**Assertions:**

- `old` → `is_hidden:true` on `local_apps`, `app_configs`; smb.conf has only `addons`, `addon_configs` with new paths
- `new` → `is_hidden:true` on `addons`, `addon_configs`; smb.conf has only `local_apps`, `app_configs`
- `both` → no `is_hidden:true` on any of the four; smb.conf has all four, legacy paths rewritten
- Test user can enumerate/connect to mode-visible shares

## Validation

1. Cleanup: `PUT /api/settings` with ORIG JSON → 200; `GET /api/settings | jq -r .standard_share_names` equals ORIG; re-disable shares disabled in baseline (`PUT /api/share/<name>/disable`); `GET /api/shares` shows all four again
2. Delete test user: `DELETE /api/user/<username>` → 204 (or 200); verify gone from `GET /api/users`
3. Check logs: addon logs no `ERROR`/`panic`; core logs no `custom_components.srat` traceback
4. Record mode payloads, share lists, testparm sections, smbclient outputs as evidence

**Success criteria:** Mode matrix passes in API + smb.conf, user access verified, settings restored, no log errors.
