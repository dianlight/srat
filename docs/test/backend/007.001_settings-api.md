# Test Case: 007.001_settings-api

## Test Objective

Verify Settings backend API: `GET /api/settings` returns full Settings DTO with user-configurable fields, `PUT /api/settings` validates and persists round-trip (hostname/workgroup regex, allow_hosts CIDR, boolean false not omitted), and data survives addon restart. Also covers `GET /api/capabilities` and `GET /api/hostname`.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Fetch baseline: `ORIG=$(curl -s http://192.168.0.68:3000/api/settings)`; `echo $ORIG | jq -e 'has("hostname") and has("workgroup") and has("allow_hosts")'` → true
3. Check DTO separation: `echo $ORIG | jq -e 'has("lib_smart_available")'` → false (must be in `/api/capabilities`, not settings); `curl -s http://192.168.0.68:3000/api/capabilities | jq -e 'has("lib_smart_available")'` → true if implemented
4. Verify `GET /api/hostname` → 200 returns string hostname (may differ from settings.hostname)
5. Save ORIG for cleanup; ensure at least one share exists is not required for settings

**If any preparation step fails** (settings 404, health not 200), **skip**.

## Execution

1. **GET baseline:** `curl -s http://192.168.0.68:3000/api/settings | jq .` → record fields: `hostname`, `workgroup`, `allow_hosts` (array), `local_master` bool, `compatibility_mode` bool, `telemetry_mode`, etc.; verify types (strings, bools, arrays)
2. **PUT valid:** construct payload by merging ORIG with `workgroup=TWG$(date +%s | tail -c4)` and `hostname=test-host-$(date +%s | tail -c4 | tr '[:upper:]' '[:lower:]')` (regex valid); `curl -X PUT http://192.168.0.68:3000/api/settings -H "Content-Type: application/json" -d "$PAYLOAD" -w "%{http_code}"` → 200; response body equals new settings (compare workgroup)
3. **GET after PUT:** `curl -s http://192.168.0.68:3000/api/settings | jq -r .workgroup` → `TWG…`; `hostname` updated
4. **Boolean false persistence:** PUT with `local_master:false` (or `allow_guest:false`) explicitly; `curl -s /api/settings | jq .local_master` → `false` (not missing); `jq -e 'has("local_master")'` → true — ensures `omitempty` not on bool DTO
5. **allow_hosts validation:** PUT with `allow_hosts:["192.168.1.0/24","::1","10.0.0.1"]` → 200; PUT with `allow_hosts:["not-an-ip"]` → 4xx (400/422) rejected; empty `[]` → 4xx if required
6. **Hostname/workgroup validation:** PUT with `hostname:"-bad-"` → 4xx; PUT with `workgroup:"bad workgroup!"` → 4xx; PUT with 64-char hostname → 4xx
7. **GET /api/hostname consistency:** `curl -s http://192.168.0.68:3000/api/hostname | jq -r .` → non-empty string
8. **Restart persistence:** `ha addons restart local_sambanas2` → wait 10s → `curl -s http://192.168.0.68:3000/api/health` 200 → `curl -s http://192.168.0.68:3000/api/settings | jq -r .workgroup` → still `TWG…`

**Assertions:**
- GET returns full DTO, PUT valid 200 round-trips
- Invalid regex/CIDR rejected with 4xx
- `false` booleans preserved (not omitted)
- Value survives restart

## Validation

1. Cleanup: `curl -X PUT http://192.168.0.68:3000/api/settings -H "Content-Type: application/json" -d "$ORIG"` → 200; verify `GET` equals `ORIG` (workgroup/hostname restored)
2. Check logs: `docker logs app_local_sambanas2 2>&1 | tail -40` → no `ERROR`/`panic`; `ha core logs | tail -20` → no `custom_components.srat` traceback
3. Verify no stale cache: after PUT, `GET /api/settings` and response of PUT body are identical within 1s (no cache lag like HardwareService example)
4. Record payloads and status codes as evidence

**Success criteria:** All PUT/GET round-trips, validations, and restart persistence pass; no log errors after cleanup.
