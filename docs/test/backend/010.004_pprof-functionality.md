# Test Case: 010.004_pprof-functionality

## Test Objective

Verify `/debug/pprof/` is present and functional in `//go:build pprof` dev builds (200 + valid samples) and absent (404) in production builds.

## Preparation

1. Addon started; define base: `API_BASE_URL="http://192.168.0.68:3000"`
2. Determine build flavour: addon log contains `server/pprof.go:14 PPROF Enabled in build` → pprof build (expect 200s); absent → production build (expect 404)
3. In SecureMode, pprof sits behind the HA middleware: loopback (host socat) is trusted so direct LAN curls get 200 on pprof builds — do not expect 401

**If any preparation step fails**, **skip**.

## Execution

1. **Index:** `curl -s ${API_BASE_URL}/debug/pprof/ -o /dev/null -w '%{http_code}\n'` → 200 (pprof build) or 404 (prod)
2. **Heap:** `curl -s '${API_BASE_URL}/debug/pprof/heap?debug=1' -o /dev/null -w '%{http_code} %{size_download}\n'` → 200, ~MB-scale body
3. **Goroutine:** `curl -s '${API_BASE_URL}/debug/pprof/goroutine?debug=1' -o /dev/null -w '%{http_code} %{size_download}\n'` → 200, KB-scale body
4. **CPU sample:** `curl -s '${API_BASE_URL}/debug/pprof/profile?seconds=3' -o /tmp/cpu.prof -w '%{http_code} %{size_download}\n'` → 200; `head -c2 /tmp/cpu.prof | od -An -tx1` → `1f 8b` (gzip magic — proves real samples, not an error page)
5. **Prod-gate (unit):** `server/pprof_disabled_test.go` (`!pprof`: route absent) and `server/pprof_enabled_test.go` (route present) cover the build-tag isolation — cite CI status, do not rebuild flavours live

**Assertions:**

- pprof build: 200 on all four endpoints, gzip-magic CPU profile
- prod build: 404 on index
- Unit tests for both flavours exist in-tree

## Validation

1. Confirm no `ERROR`/panic in addon log correlates with profile collection
2. Record status codes, byte sizes, gzip magic bytes

**Success criteria:** Live endpoints match the build flavour; CPU profile is genuine sampled data; tag isolation covered by unit tests.
