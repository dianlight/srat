# Test Case: 002.005_volume-sensor-parity

## Test Objective

Verify HA-exposed SRAT volume sensors mirror `GET /api/volumes` live state (regression for srat#1394): disk sensor `size`/`serial` equal the volumes entry, partition sensor `device`/`mount`/`share` state agrees with the partition's `mount_point_data` (mounted + shared partitions must not report `unmounted`/`0` counts), and values refresh after mount/share mutations without a restart.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. HA states API reachable: `curl -sk -H "Authorization: Bearer $HA_TOKEN" https://192.168.0.68/api/states/sensor.srat_samba_process_status` → 200 (if 401, **skip** — no HA user credential)
3. Pick disk `D` + partition `P` from `GET /api/volumes`; record `size`, `serial`, mount state, share name
4. Confirm HA entities exist and are not `unknown`: disk sensor for `D`, partition sensor for `P`

**If any preparation step fails** (HA API unreachable, entities missing), **skip**.

## Execution

1. **Disk parity:** read disk sensor attributes → assert `size_bytes` == `D.size`, `serial` == `D.serial`, `device` non-null
2. **Partition parity:** read partition sensor → assert `state` matches live mount/share (`mounted`/`shared`/`unmounted`), `mount_count`/`share_count` match `mount_point_data`/`share`, `device` non-null
3. **Freshness:** mutate (mount/unmount or attach/detach a share on `P`), wait ≤60 s for coordinator refresh → re-read sensors → values track the mutation (guards shallow-copy staleness)

**Assertions:**

- Sensor attributes equal live REST values for both disk and partition
- Post-mutation re-read reflects the new state within 60 s
- No `custom_components.srat` tracebacks in HA core logs

## Validation

1. Restore pre-test mount/share state; re-read sensors → consistent again
2. HA core logs: no new `Traceback`/`ERROR` from `custom_components.srat`; addon logs `panic|FATAL` → empty
3. Record sensor JSON + REST excerpts as evidence

**Success criteria:** Sensors mirror REST before and after mutation; baseline restored; logs clean.
