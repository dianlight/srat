# Test Case: 007.005_mdns-direct-protect-on

## Test Objective

Verify direct addon mDNS registration (`mdns_registration=true` + `use_component_mdns_proxy=false`, no custom component) still broadcasts a correct and resolvable `_smb._tcp` service while the addon runs with protection mode ON, and that the broadcast resolves both from the HA host and from this Mac.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `state: started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Define base: `API_BASE_URL="http://192.168.0.68:3000"`
3. Enable protection mode ON: Supervisor UI (Addon → Protection mode ON) or `ha addons update local_sambanas2 --protected=true` if supported → `ha addons restart local_sambanas2` → wait 10s → confirm via `ha addons info local_sambanas2 | grep -i protected` → `true` (or WS hello `protected_mode:true`); record toggle method as evidence
4. No custom component step: do not deploy/reload `custom_components/srat` in this case
5. Save baseline: `ORIG=$(curl -s ${API_BASE_URL}/api/settings)`; save to `/tmp/orig_mdns_on.json`; record `hostname`
6. Compute expected instance: `echo "$HOSTNAME" | tr '[:lower:]' '[:upper:]' | sed 's/[^A-Z0-9]/-/g' | cut -c1-15` → `$EXPECTED_INSTANCE`
7. Mac prerequisites: same LAN as 192.168.0.68, `dns-sd` available

**If any preparation step fails** (cannot enable protected mode, API unreachable, Mac off-LAN), **skip** and document reason.

## Execution

1. **Enable direct mDNS:** `jq '.mdns_registration=true | .use_component_mdns_proxy=false' /tmp/orig_mdns_on.json | curl -X PUT ${API_BASE_URL}/api/settings -H "Content-Type: application/json" -d @- -w "%{http_code}\n"` → 200; `GET | jq -r '.mdns_registration,.use_component_mdns_proxy'` → `true`, `false`
2. **Restart to apply:** `ha addons restart local_sambanas2` → wait 10s → health 200 → re-confirm protected still `true`
3. **Addon log assertion:** `ha addons logs local_sambanas2 | grep -a 'mdns'` → `registering direct mDNS` with `"instance":"$EXPECTED_INSTANCE"`, port 445; no `registration failed`, no `panic`
4. **HA-host browse:** `docker exec addon_local_sambanas2 sh -c "avahi-browse -a -t -p 2>/dev/null | grep -i '_smb._tcp'"` (fallback `app_local_sambanas2`) → finds `$EXPECTED_INSTANCE`
5. **Mac browse (MANDATORY):** `timeout 15 dns-sd -B _smb._tcp local.` → lists `$EXPECTED_INSTANCE._smb._tcp.local.` within 15s
6. **Mac resolve (MANDATORY):** `timeout 15 dns-sd -L "$EXPECTED_INSTANCE" _smb._tcp local.` → port `445`, TXT `path=/`, host → 192.168.0.68 (`dig +short <host>.local`)
7. **Protect-mode side assertion:** `PUT /api/settings` round-trip still 200 under protected mode; volume mutating endpoints remain guarded (spot-check `POST /api/volumes/mount` → 403 if applicable) to prove protected mode is genuinely ON while mDNS works

**Assertions:**

- Protected mode confirmed ON during the whole case
- Direct registration log correct, no error
- Remote browse + Mac browse + Mac resolve all pass with identical instance/port/TXT
- Settings write still works; protected-mode guards elsewhere unaffected

## Validation

1. Cleanup: restore `/tmp/orig_mdns_on.json` via PUT → 200; toggle protection mode back OFF (UI or CLI) → restart → wait 10s → health 200 → confirm protected `false` (leave environment as found; record if left ON by request)
2. Check logs: `ha addons logs local_sambanas2 | tail -30` → no `ERROR`/`panic`; `ha core logs | tail -10` → no traceback
3. Record evidence: protected toggle method, PUT/GET payloads, log lines, avahi output, Mac `dns-sd -B`/`-L` outputs with timestamps
4. Note deviations (toggle path, container name, timing extensions beyond 15s with justification)

**Success criteria:** mDNS broadcast identical and resolvable with protect ON; dual-side (HA host + this Mac) verification passes; environment restored; no log errors.
