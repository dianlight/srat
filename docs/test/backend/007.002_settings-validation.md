# Test Case: 007.002_settings-validation

## Test Objective

Verify backend validation for `PUT /api/settings`: hostname (`HOSTNAME_REGEX` `^[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?$`, 1-63), workgroup (`WORKGROUP_REGEX` `^[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,13}[a-zA-Z0-9])?$`, 1-15), `allow_hosts` entries must be IPv4/IPv6/CIDR (`isValidIpAddressOrCidr`), required handling, and boolean `false` not omitted. Expects `400/422` for invalid, `200` for valid.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Define base URL: `API_BASE_URL="http://192.168.0.68:3000"`
3. Fetch baseline: `ORIG=$(curl -s ${API_BASE_URL}/api/settings)`; `echo $ORIG | jq -e 'has("hostname") and has("workgroup")'` → true; save to `/tmp/orig_settings_validation.json`
4. Verify current DTO separation: `echo $ORIG | jq -e 'has("lib_smart_available")'` → false (must be in `/api/capabilities`)
5. Ensure `read_only:false` (if true skip validation, would be 403)

**If any preparation fails**, **skip**.
