# Test Case: 002.002_smart-device-details

## Test Objective

Verify per-disk SMART details via the SRAT API (`GET /api/disk/{disk_id}/smart/info|status|health`): SMART-capable disks return attributes and health, while disks behind unknown USB bridges fail gracefully (clear error, no `panic`), and the enable flow toggles monitoring state.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Define helpers: `export API=http://192.168.0.68:3000`; pick disk ids: `curl -s $API/api/volumes | jq -r '.[].id'` → note one internal SSD id (e.g. `ata-WD_PC_SN740_SDDPNQD-512G-2006_23482W805056`) as `SMART_DISK` and one USB id (e.g. `usb-Flash_Disk_3.0_7966051146147389472-0:0`) as `USB_DISK`
3. Check capability gate: `curl -s $API/api/capabilities | jq -r '.lib_smart_available'` → note value; if `false`, SMART-info assertions are skipped and only graceful-degradation is verified

**If any preparation step fails** (addon not running, no disks detected, API unreachable), the test must be **skipped**.

## Execution

1. Fetch SMART info for `SMART_DISK`: `curl -s $API/api/disk/$SMART_DISK/smart/info -w "\nHTTP:%{http_code}\n"` → record status; on 200 verify JSON contains device/attribute fields (not empty object)
2. Fetch SMART status and health for the same disk: `GET /api/disk/$SMART_DISK/smart/status` → 200; `GET /api/disk/$SMART_DISK/smart/health` → 200 with a health indicator field
3. Fetch SMART info for `USB_DISK` (unknown bridge): expect a non-200 (4xx/5xx) with a clear `detail` mentioning the bridge/device (e.g. `Unknown USB bridge [0x048d:0x1234]`), **not** an empty 500 and not a hang (assert response arrives <10s)
4. Toggle monitoring (only on a SMART-capable disk — skip with note if none exists on the box): `curl -s -X POST $API/api/disk/$SMART_DISK/smart/disable` → 200; then `POST .../smart/enable` → 200; re-fetch `status` → reflects the toggle. Endpoints take **no body** (separate `/enable` and `/disable` routes). On boxes where every disk sits behind an unknown USB bridge, both calls return 500 (`Failed to enable/disable SMART`) — record as **fail-toggle** (spec gap proven 2026-09-17: `lib_smart_available:true` means the library is present, not that any disk is capable)
5. Check addon logs for `panic`/`FATAL` after the unknown-bridge call: `ha addons logs local_sambanas2 | tail -n 20 | grep -iE "panic|FATAL"` → empty (SMART WARN lines about bridges are expected baseline noise, not failures)

**Assertions:**

- SMART-capable disk: `info`/`status`/`health` return 200 with non-empty payloads
- Unknown-bridge disk: clear error mentioning bridge/device, fast (<10s), no `panic`
- Enable toggle round-trips 200 and is reflected in `status` (capable disk only; on a box with no capable disk → recorded fail-toggle, not a pass)

## Validation

1. Confirm `GET /api/volumes` still 200 and disk list unchanged (no side effects from SMART probes)
2. Confirm frontend Dashboard → Disk Health panel loads without errors (served via `API_URL=http://192.168.0.68:3000/ SUPERVISOR_URL=http://192.168.0.68/ mise run //frontend:dev:remote`)
3. Record statuses and payload summaries as evidence

**Success criteria:** Per-disk SMART details verified where available, graceful degradation where not, toggle works, no log errors.
