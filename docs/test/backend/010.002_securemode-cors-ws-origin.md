# Test Case: 010.002_securemode-cors-ws-origin

## Test Objective

Verify SecureMode origin enforcement (`dto.IsOriginAllowed` shared by CORS and WS): browser evil origins fail closed, empty (non-browser) origins stay allowed, dev/door-open stays permissive.

## Preparation

1. Door-closed SecureMode state per 010.001 Preparation (steps 3–5), same binary check
2. Define base: `API_BASE_URL="http://192.168.0.68:3000"`
3. No `--ingress-origin`/`--allowed-origins` flags in `ps` args (fail-closed baseline: no origins configured)

**If any preparation step fails**, **skip**.

## Execution

1. **CORS preflight evil:** `curl -s -X OPTIONS ${API_BASE_URL}/api/health -H 'Origin: https://evil.example' -H 'Access-Control-Request-Method: GET' -D - -o /dev/null` → `204` with NO `Access-Control-Allow-Origin` header (fail-closed)
2. **WS evil origin:** `curl -s -H 'Connection: Upgrade' -H 'Upgrade: websocket' -H 'Origin: https://evil.example' -H 'Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==' -H 'Sec-WebSocket-Version: 13' ${API_BASE_URL}/ws -D - -o /dev/null` → `403 Forbidden`
3. **WS empty origin:** same without `Origin` header → `101 Switching Protocols` (non-browser HA component allowed)
4. **Door-open contrast (optional, needs restart):** set `leave_front_door_open=true` (full options object) + restart → CORS reflects `Access-Control-Allow-Origin: https://evil.example`, WS evil → `101`; restore door-closed afterwards unless suite ends open

**Assertions:**

- Closed: no ACAO echo, WS 403 on evil, WS 101 on empty origin
- Open: ACAO reflected, WS 101 on evil (permissive dev)
- Unit coverage exists in-tree: `server/cors_test.go`, `server/origins_test.go`, `api/ws_origin_test.go`, `dto/origins_test.go`

## Validation

1. Check logs for new `ERROR`/tracebacks; record all status codes + headers
2. If step 4 ran, confirm final addon options match suite plan (door state + develop channel)

**Success criteria:** Closed mode fails shut on evil origins and admits empty ones; open mode permissive; evidence recorded.
