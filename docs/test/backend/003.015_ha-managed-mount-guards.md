# Test Case: 003.015_ha-managed-mount-guards

## Test Objective

Verify that SRAT refuses to mount, unmount, format, check or set-label on Home-Assistant-managed volumes (paths under `/media/`, `/share/`, `/backup/`), returning a 4xx and leaving state untouched. Also verify automount is skipped for HA-managed partitions.

## Preparation

1. Ensure the SRAT addon is running: `ha apps info local_sambanas2` → `started`; health 200
2. Pick an HA-managed (unmounted) partition from `GET /api/volumes` whose `mount_point` starts with `/media/`, `/share/` or `/backup/` and `is_ha_mounted == true` → note `PART_ID`
3. If no HA-managed partition exists, the test must be **skipped**

**If any preparation step fails**, the test must be **skipped**.

## Execution

1. `POST /api/volume/mount` with `{ "partitionId": "{PART_ID}" }` → expect 4xx (rejected); record status code
2. `POST /api/volume/unmount` with `{ "partitionId": "{PART_ID}" }` → expect 4xx (rejected)
3. `POST /api/filesystem/format` with `{ "partitionId": "{PART_ID}", "filesystemType": "ext4", "force": false }` → expect 4xx
4. `POST /api/filesystem/check` with `{ "partitionId": "{PART_ID}" }` → expect 4xx
5. `POST /api/filesystem/label` with `{ "partitionId": "{PART_ID}", "label": "SRATTEST" }` → expect 4xx
6. `GET /api/volumes` → confirm `PART_ID` state unchanged (still unmounted, no label change)

**Assertions:**

- Every mutating endpoint returns 4xx for an HA-managed partition
- No state mutation occurred (mount_point/label unchanged before/after)
- Addon logs show the guard reason (HA-managed / path prefix)

## Validation

1. Check addon logs: no panic/ERROR beyond the expected guard rejections
2. Confirm addon state `started` and health 200

**Success criteria:** All HA-managed mutating ops rejected with 4xx; state untouched; logs clean.
