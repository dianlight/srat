# Test Case: 010.005_door-open-direct-access

## Test Objective

Verify that with `leave_front_door_open=true` (no `-addon` flag, SecureMode off) direct LAN access to the API/CORS/WS/pprof is permissive, and that the addon ends in the lab-default state.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `state: started`
2. Set door open with full options (options call REPLACES the whole object — always send all keys): `srat_update_channel=develop, auto_update=true, log_level=info, leave_front_door_open=true, disable_ipv6=true, clean_upgrade_dir=false, factory_reset=false, use_external_kernel_modules=true`; restart addon; wait ~40s
3. Confirm: `ps` args contain NO `-addon`; `telemetry configured ... environment=development` in log; binary md5 matches upgrade-dir (full restarts recreate the container — the develop watcher reinstalls from the host-persisted upgrade dir; verify before trusting results)
4. Define base: `API_BASE_URL="http://192.168.0.68:3000"`

**If any preparation step fails**, **skip**.

## Execution

1. **Direct API:** `curl -s ${API_BASE_URL}/api/health` → 200; `curl -s ${API_BASE_URL}/api/shares` → 200 (no auth headers needed)
2. **CORS permissive:** preflight with `Origin: https://evil.example` → `204` WITH `Access-Control-Allow-Origin: https://evil.example`
3. **WS permissive:** upgrade with `Origin: https://evil.example` → `101 Switching Protocols`
4. **pprof:** `curl -s ${API_BASE_URL}/debug/pprof/ -o /dev/null -w '%{http_code}\n'` → 200 on dev builds (see 010.004)

**Assertions:**

- All direct/API/CORS/WS/pprof probes permissive (200/204+ACAO/101/200)
- No `-addon` in process args

## Validation

1. Final lab-default check: options show `leave_front_door_open=true` + develop channel; `ha addons info` → `started`; log `ERROR|FATAL|panic` count → 0
2. Record evidence: ps line, all status codes, options dump

**Success criteria:** Door-open direct access fully permissive with lab-default options restored; no log errors.
