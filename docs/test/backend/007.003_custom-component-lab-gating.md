# Test Case: 007.003_custom-component-lab-gating

## Test Objective

Verify the `ha_custom_component` alpha lab feature gates all missing-component notify/repair/alert paths: with lab mode off (or a production build where the alpha is omitted) the custom-component endpoints return 403, `/api/problems` carries no `custom_component_*` keys, and no `problem` WS events fire for them; with lab on in a dev/prerelease build the status endpoint returns 200 and the missing-component problem is raised normally.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Record build: `curl -s http://192.168.0.68:3000/api/lab_features` → note whether `ha_custom_component` is present (dev/prerelease) or omitted (production); if the endpoint 404s the binary predates the gate — stop, redeploy first
3. Fetch baseline: `ORIG=$(curl -s http://192.168.0.68:3000/api/settings)`; note `experimental_lab_mode`; `curl -s http://192.168.0.68:3000/api/problems | jq -r '.[].problem_key'` → note `BASE_PROBLEMS`
4. Confirm component state: `docker exec app_local_sambanas2 ls /homeassistant/custom_components/srat` → expect missing (not installed) unless the lab-on path is under test

**If any preparation fails** (health not 200, `lab_features` 404), **skip**.

## Execution

1. Lab-off gate (works on any build): ensure `experimental_lab_mode:false` via `GET /api/settings`; `GET /api/settings/homeassistant/custom-component/status` → 403; `POST .../install`, `POST .../upgrade`, `DELETE .../custom-component` → 403 each
2. Stale-row cleanup: `GET /api/problems` → no `custom_component_*` keys (the 403 status call dismisses leftovers via `SyncIssueStatus`); if a stale key exists, repeat step 1 once and re-check
3. WS silence: capture `curl -sN -H "Connection: Upgrade" http://192.168.0.68:3000/ws` for 10 s → zero `event: problem` frames carrying `custom_component_` keys
4. Lab-on positive path (dev/prerelease builds only; skip on production): `PUT /api/settings` with `experimental_lab_mode:true` (full-body update) → 200; `lab_features` shows `ha_custom_component available:true`; `GET .../status` → 200 with `installed:false connected:false`; `GET /api/problems` contains `custom_component_missing` with `status:created`
5. Restore lab mode: `PUT /api/settings` with `ORIG` body → 200; `DELETE /api/problems/custom_component_missing` → 204 if step 4 created it

**Assertions:**

- Lab off or production: endpoints 403, problems clean, WS quiet for `custom_component_*`
- Lab on (non-production): status 200, missing problem created, WS `problem` event broadcast

## Validation

1. Cleanup: `GET /api/settings | jq .experimental_lab_mode` equals baseline; `GET /api/problems` equals `BASE_PROBLEMS` (dismiss any test-created keys); component dir unchanged from step 4 of Preparation
2. Check logs: `ha apps logs local_sambanas2 | tail -30` → no `panic`/`FATAL`; version-skip lines (`same version or older`) only if a redeploy was attempted mid-run
3. Record evidence: endpoint status codes, problems before/after, WS capture excerpt

**Success criteria:** gating holds in both directions with settings and filesystem restored to baseline.
