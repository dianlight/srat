# Test Case: 007.007_mdns-hostname-rename

## Test Objective

Verify that changing `hostname` while direct mDNS is active (`mdns_registration=true` + `use_component_mdns_proxy=false`, no custom component) re-registers the `_smb._tcp` service under the new NetBIOS-sanitized instance name (uppercase, truncate 15 chars, non-alphanumeric → `-`), withdraws the old instance, and that both states are observable from this Mac as well as the HA host.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Define base: `API_BASE_URL="http://192.168.0.68:3000"`
3. Protection mode: record current value; run as-is (direct mDNS is protection-independent per 007.004/007.005)
4. Save baseline: `ORIG=$(curl -s ${API_BASE_URL}/api/settings)` → `/tmp/orig_mdns_rename.json`; record `ORIG_HOST`
5. Enable direct mode first: PUT `mdns_registration=true`, `use_component_mdns_proxy=false` → 200 → restart → Mac `dns-sd -B _smb._tcp local.` shows `$OLD_INSTANCE` (NetBIOS sanitize of `$ORIG_HOST`); if no initial broadcast, **skip**
6. Pick a new hostname satisfying `HOSTNAME_REGEX`, clearly different after sanitize, e.g. `NEW_HOST="mdns-rename-test"` → `$NEW_INSTANCE="MDNS-RENAME-TE"` (15-char truncation check: `echo "$NEW_HOST" | tr '[:lower:]' '[:upper:]' | sed 's/[^A-Z0-9]/-/g' | cut -c1-15`)
7. Mac prerequisites: same LAN as 192.168.0.68, `dns-sd` available

**If any preparation step fails** (no initial broadcast, API unreachable, Mac off-LAN), **skip**.

## Execution

1. **Rename:** `jq --arg h "$NEW_HOST" '.hostname=$h' /tmp/orig_mdns_rename.json | curl -X PUT ${API_BASE_URL}/api/settings -H "Content-Type: application/json" -d @- -w "%{http_code}\n"` → 200 (no restart — reconfigure must be live via the settings-change event tearing down and re-registering)
2. **Addon log assertion (docker logs, NOT `ha logs` — window is ~100 lines):** `docker exec` host: `docker logs app_local_sambanas2 --tail 3000 2>&1 | grep -a 'mdns'` → contains `shutting down existing direct mDNS registration` followed by `registering direct mDNS` with `"instance":"$NEW_INSTANCE"`; no `registration failed`
3. **Mac browse:** `timeout 30 dns-sd -B _smb._tcp local.` → `$NEW_INSTANCE` appears; `$OLD_INSTANCE` disappears within 60s (goodbye/TTL grace — wait full window before failing)
4. **Mac resolve:** `timeout 15 dns-sd -L "$NEW_INSTANCE" _smb._tcp local.` → port `445`, TXT `path=/`, target resolves to `192.168.0.68` (`dns-sd -Q <target> A IN`)
5. **HA-host check:** `getent hosts $NEW_INSTANCE.local` and direct-mode log line agree on instance spelling

**Assertions:**

- PUT 200 with no restart still re-registers (live reconfigure path, not only OnStart)
- New instance exactly equals NetBIOS sanitize of new hostname (uppercase/15-char/non-alnum rules)
- Old instance withdrawn on both sides after TTL grace
- Port 445 + TXT `path=/` unchanged

## Validation

1. Cleanup: restore `/tmp/orig_mdns_rename.json` via PUT → 200 → restart → health 200 → Mac browse shows `$OLD_INSTANCE` again, `$NEW_INSTANCE` gone
2. Check logs: `docker logs app_local_sambanas2 --tail 300 2>&1 | grep -a -iE 'FATAL|panic|registration failed'` → empty
3. Record evidence: PUT/GET payloads, mDNS service log lines, Mac `dns-sd -B`/`-L` outputs with timestamps
4. Note deviations (restart required vs live, grace extensions)

**Success criteria:** Rename propagates live to a correctly sanitized instance on both sides; old instance withdrawn; environment restored; no log errors.
