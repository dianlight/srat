# Test Case: 007.008_mdns-interface-whitelist

## Test Objective

Verify the `interfaces` whitelist restricts direct addon mDNS registration (`mdns_registration=true` + `use_component_mdns_proxy=false`, no custom component) to the named interfaces: the registration log lists only whitelisted eligible interfaces, loopback/container/virtual (`lo`, `docker*`, `veth*`, `hassio*`, `br-*`) and down interfaces are always excluded, and an empty whitelist registers on all eligible interfaces.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Define base: `API_BASE_URL="http://192.168.0.68:3000"`
3. Save baseline: `ORIG=$(curl -s ${API_BASE_URL}/api/settings)` → `/tmp/orig_mdns_iface.json`; record `interfaces` array
4. Enumerate addon-visible interfaces: `docker exec app_local_sambanas2 sh -c "ls /sys/class/net"` (fallback `ip -o link show`) → identify at least one eligible physical interface (expect `enp0s25`, `wlp2s0` on the test host) plus excluded ones (`lo`, `docker*`, `hassio*`)
5. Enable direct mode: PUT `mdns_registration=true`, `use_component_mdns_proxy=false` → 200 → restart → `docker logs ... | grep -a 'registering direct mDNS'` shows baseline `ifaces` list; if no registration, **skip**
6. Mac prerequisites: same LAN, `dns-sd` available (service must stay resolvable throughout)

**If any preparation step fails** (no eligible interface, no registration), **skip**.

## Execution

1. **Whitelist single interface:** `jq '.interfaces=["enp0s25"]' /tmp/orig_mdns_iface.json | curl -X PUT ${API_BASE_URL}/api/settings -H "Content-Type: application/json" -d @- -w "%{http_code}\n"` → 200 (adjust name to a real eligible interface from step 4; if only one eligible exists, use a bogus-but-wellformed second entry `["enp0s25","no-such0"]` to prove unknown names are ignored, not fatal)
2. **Log assertion:** `docker logs app_local_sambanas2 --tail 3000 2>&1 | grep -a 'registering direct mDNS' | tail -1` → `ifaces` contains ONLY the whitelisted eligible interface (no `lo`, no `docker*`/`veth*`/`hassio*`/`br-*`, no down interfaces)
3. **Service still resolvable:** Mac `timeout 15 dns-sd -L "$EXPECTED_INSTANCE" _smb._tcp local.` → port 445 (whitelisting must not kill the announcement on the remaining interface)
4. **Excluded-prefix rejection:** PUT `interfaces=["lo"]` → 200 accepted but log shows reconfigure with EMPTY `ifaces` (loopback always excluded, never registered); Mac browse still resolves via prior announcement or shows none — record actual behavior, do not fail on TTL lag (wait 60s)
5. **Empty whitelist restores all-eligible:** PUT `interfaces=[]` → 200 → log `ifaces` returns to full eligible set from step 5 baseline

**Assertions:**

- Whitelist narrows `ifaces` to named eligible interfaces only
- Excluded prefixes and down interfaces never appear, even when explicitly listed
- Unknown names are ignored without error
- Service remains resolvable while at least one eligible interface is listed
- Empty whitelist = all eligible interfaces

## Validation

1. Cleanup: restore `/tmp/orig_mdns_iface.json` via PUT → 200 → restart → health 200 → log `ifaces` equals baseline
2. Check logs: `docker logs app_local_sambanas2 --tail 300 2>&1 | grep -a -iE 'FATAL|panic|registration failed'` → empty
3. Record evidence: interface enumeration, PUT payloads, `registering direct mDNS` lines per step, Mac resolve outputs
4. Note deviations (interface names differ on other hosts — always enumerate first, never hardcode)

**Success criteria:** Whitelist honored exactly (eligible-only, exclusions absolute, unknown ignored, empty = all); service resolvable throughout; environment restored; no log errors.
