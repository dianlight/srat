# Test Case: 006.004_repair-problem-mirror-parity

## Test Objective

Verify Repair↔Problem mirror parity over the live backend: every `repair_command` frame on the WebSocket (`ws://192.168.0.68:3000/ws`, SSE `id:`/`event:`/`data:`) has a matching `/problems` entry with mapped severity and lifecycle status, and lifecycle transitions (created → updated → ignored/fixed/dismissed) stay in sync. Mirror failures must be best-effort (warn-only): a sync failure never breaks the primary repair operation.

## Preparation

1. Ensure the SRAT addon is running: `ha apps info local_sambanas2` → `started`; health 200
2. Open a WebSocket listener in the background (real RFC6455 handshake **including an `Origin` header** — plain `curl -N` without `Origin` returns `400 Bad Request`; the endpoint speaks WebSocket with SSE-style text payloads, not plain SSE): `python3 docs/test/ws_listen.py /tmp/srat_repair.log 300 & echo $! > /tmp/srat_repair.pid`; wait 5 s and confirm `hello`/`heartbeat` frames arrive in `/tmp/srat_repair.log`
3. Record baseline: `GET /api/problems` → note keys, `severity`, `status` per entry; `GET /api/settings` → note `alert_protected_mode`
4. Ensure protection mode is ON and `protected_mode` problem is active with `ignored: false` (re-enable via `PUT /api/problems/protected_mode` if needed)

**If any preparation step fails** (WS unreachable, no active problem), the test must be **skipped**.

## Execution

1. Ignore: `PUT /api/problems/protected_mode` with `ignored: true, status: ignored` → 200; within 10 s assert a `repair_command` frame for `protected_mode` appears in `/tmp/srat_repair.log` and `GET /api/problems/protected_mode` shows `ignored: true`
2. Re-enable: `PUT` with `ignored: false, status: created` → 200; within 10 s assert matching `repair_command` frame and problem shows `ignored: false`, `status: created`
3. Dismiss: `PUT /api/settings` with `alert_protected_mode: false` → 200; within 10 s assert the problem key disappears from `GET /api/problems` (REMOVE/deleted event or absence)
4. Re-arm: `PUT /api/settings` with `alert_protected_mode: true` → assert the problem reappears with `ignored: false` and a creation `repair_command` frame is emitted
5. Kill the listener: `kill $(cat /tmp/srat_repair.pid)`; restore baseline settings

**Assertions:**

- Every observed `repair_command` frame has a matching `/problems` entry (same key) with consistent severity/status mapping — no orphan frames, no orphan problems
- Each mutation (ignore / re-enable / dismiss / re-arm) converges on both surfaces within 10 s
- Addon logs show at most `WARN` for mirror sync issues, never a failed primary operation caused by the mirror

## Validation

1. `GET /api/problems/protected_mode` → baseline state (`ignored: false`)
2. `GET /api/settings` → `alert_protected_mode: true` (baseline)
3. Check addon logs: `ha apps logs local_sambanas2 | tail -n 30 | grep -iE "panic|FATAL"` → empty; `grep -i "sync repair.*problem"` → at most WARN lines
4. Confirm addon state `started` and health 200; listener process reaped

**Success criteria:** Repair commands and problems stay 1:1 consistent through the full lifecycle with fresh payloads; mirror is warn-only; baseline restored; logs clean.
