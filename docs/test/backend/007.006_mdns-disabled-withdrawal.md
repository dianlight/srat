# Test Case: 007.006_mdns-disabled-withdrawal

## Test Objective

Verify that disabling the master switch (`mdns_registration=false`, no custom component) withdraws the `_smb._tcp` broadcast so it disappears both from the HA host and from this Mac, with no stale direct registration left running.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Define base: `API_BASE_URL="http://192.168.0.68:3000"`
3. Protection mode: record current value (`ha addons info local_sambanas2 | grep -i protected`); run as-is (state both values in evidence); do not toggle mid-case
4. Start from ENABLED state: ensure `mdns_registration=true` + `use_component_mdns_proxy=false` first (PUT → 200 → restart → Mac `dns-sd -B` sees instance); if instance never appears, **skip** (withdrawal cannot be tested without a prior broadcast). Save `ORIG_ENABLED` to `/tmp/orig_mdns_wd.json` and `$EXPECTED_INSTANCE`
5. Mac prerequisites: same LAN, `dns-sd` available; note mDNS TTL grace (up to ~120s for goodbye propagation on some resolvers)

**If any preparation step fails** (cannot establish initial broadcast), **skip**.

## Execution

1. **Disable mDNS:** `jq '.mdns_registration=false' /tmp/orig_mdns_wd.json | curl -X PUT ${API_BASE_URL}/api/settings -H "Content-Type: application/json" -d @- -w "%{http_code}\n"` → 200; `GET | jq -r .mdns_registration` → `false`
2. **Restart to apply:** `ha addons restart local_sambanas2` → wait 10s → health 200
3. **Addon log assertion:** `ha addons logs local_sambanas2 | grep -a 'mdns'` → shutdown path (no `registering direct mDNS` after restart; may show settings-changed reconfigure without registration); no `registration failed`/`panic`
4. **HA-host absence:** `docker exec addon_local_sambanas2 sh -c "avahi-browse -a -t -p 2>/dev/null | grep -i '_smb._tcp'"` (fallback `app_local_sambanas2`) → empty for `$EXPECTED_INSTANCE` (allow 30s grace, retry once after 30s before failing)
5. **Mac absence (MANDATORY):** `timeout 60 dns-sd -B _smb._tcp local.` → `$EXPECTED_INSTANCE` absent for the full window (run full 60s; goodbye/TTL may take time — absence at 60s is the assertion, not instant). Record full output
6. **Mac resolve negative:** `timeout 10 dns-sd -L "$EXPECTED_INSTANCE" _smb._tcp local.` → no answer (timeout with zero records); do not treat cached success within first 30s as pass — repeat at 60s+ if first attempt still resolves
7. **Re-enable sanity (optional but recommended):** PUT `mdns_registration=true` → 200 → restart → Mac `dns-sd -B` sees instance again → proves toggle takes effect, not stuck; then disable again if cleanup requires off state

**Assertions:**

- PUT 200, GET `false`
- No direct registration log after restart
- Instance absent on HA host browse and on Mac browse (60s window)
- Mac resolve returns no records after TTL grace
- Re-enable brings it back (proves the toggle takes effect, optional)

## Validation

1. Cleanup: restore original settings from `/tmp/orig_mdns_wd.json` if ORIG had mDNS off, else leave enabled only if that was the pre-case state — default restore ORIG → PUT 200 → restart → health 200; state final `mdns_registration` in evidence
2. Check logs: `ha addons logs local_sambanas2 | tail -30` → no `ERROR`/`panic`; `ha core logs | tail -10` → clean
3. Record evidence: PUT/GET payloads, log lines, avahi outputs (before/after), Mac `dns-sd -B` 60s output + `dns-sd -L` negative output with timestamps
4. Note deviations (grace extensions, container name, whether re-enable sanity was run)

**Success criteria:** Disable withdraws the service on both sides after TTL grace; no stale broadcast on Mac or host; cleanup restored; no log errors.
