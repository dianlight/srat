# Test Case: 003.017_ha-native-storage-mode

## Test Objective

Verify the user-configurable HA native storage mode (`off|on|auto`) and the version-gated capability flag: `GET /api/capabilities` exposes `ha_native_storage_supported`, `GET/PUT /api/settings` round-trips `ha_native_storage_mode`, and the mount flow honors the effective mode.

> Status note: this capability is not implemented yet (change 055 tasks 1.x–3.x unchecked; `HaNativeStorageMode` and `HaNativeStorageSupported` do not exist in the codebase). The case is expected to **fail** until it lands; it is a tracking test, not a validation of shipped behavior.

## Preparation

1. Ensure the SRAT addon is running: `ha apps info local_sambanas2` → `started`; health 200
2. Record the HA versions: `ha supervisor info` and `ha core info` (need Supervisor >= 2026.10.1 and Core >= 2026.11 for `supported=true`)
3. Save a pristine settings snapshot: `GET /api/settings` → `ORIG`

**If any preparation step fails**, the test must be **skipped**.

## Execution

1. `GET /api/capabilities` → assert `ha_native_storage_supported` is present and equals (`Supervisor >= 2026.10.1` AND `Core >= 2026.11`)
2. `GET /api/settings` → assert `ha_native_storage_mode` is present and defaults to `"auto"`
3. `PUT /api/settings` with `ha_native_storage_mode: "off"` → 2xx; re-`GET` and assert persisted `"off"`; assert the volume mount flow offers only the local backend
4. `PUT /api/settings` with `ha_native_storage_mode: "on"` → 2xx; re-`GET` and assert persisted `"on"`; with an unsupported version the volumes page reports "not supported on this HA version"
5. `PUT /api/settings` with `ha_native_storage_mode: "bogus"` → expect 4xx (invalid enum rejected)
6. Restore settings from `ORIG` (never chain restores)

**Assertions:**

- Capability flag present and matches the version threshold
- Mode round-trips through `GET/PUT /api/settings` and defaults to `auto`
- Invalid mode rejected with 4xx
- Mount flow and volumes page reflect the effective mode

## Validation

1. Re-`GET /api/settings` and confirm the value equals `ORIG` after restore
2. Addon logs show no panic/ERROR from the setting changes

**Success criteria:** Capability and mode are exposed, persisted, validated, and drive the mount/volumes behavior.
