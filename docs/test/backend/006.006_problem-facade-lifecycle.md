
# Test Case: 006.006_problem-facade-lifecycle

## Test Objective

Verify the new `service/problem` repair-mirroring facade end-to-end over REST only (no WebSocket listener): repair lifecycle changes are mirrored into `GET /api/problems` with correct status/severity mapping, and mirror operations remain best-effort (primary repair operation always succeeds, mirror failures surface at most as WARN in addon logs). Complements 006.004, which verifies the same path via WS frames.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/api/health` → `200`
2. Record baseline: `GET http://localhost:3000/api/problems` → note keys, `severity`, `status`; `GET http://localhost:3000/api/settings` → note `alert_protected_mode`
3. Ensure protection mode is ON and the `protected_mode` problem exists (`GET http://localhost:3000/api/problems/protected_mode` → 200); re-enable via `PUT /api/problems/protected_mode` if missing
4. Clear addon log cursor: `ha addons logs local_sambanas2 | tail -n 5`

**If any preparation step fails** (addon not started, health not 200, `protected_mode` problem absent), the test must be **skipped**.

## Execution

1. Lifecycle→status mapping: `PUT /api/problems/protected_mode` with `{"ignored": true, "status": "ignored"}` → 200; within 10 s `GET /api/problems/protected_mode` shows `status: ignored` (facade `MapRepairLifecycleStatus` path)
2. Revert: `PUT /api/problems/protected_mode` with `{"ignored": false, "status": "created"}` → 200; within 10 s problem shows `status: created`, `ignored: false`
3. Dismiss path: `PUT /api/settings` with `{"alert_protected_mode": false}` → 200; within 10 s `GET /api/problems/protected_mode` → 404 (or key absent from `GET /api/problems`) — facade `DismissProblem` ran
4. Re-create path: `PUT /api/settings` with `{"alert_protected_mode": true}` → 200; within 10 s `protected_mode` problem reappears with `status: created` and its baseline `severity` — facade `SyncProblemFromCommand` ran
5. Record primary-operation result for every step above (all must be 2xx regardless of mirror outcome)

**Assertions:**

- Every mutation returns 2xx on the primary API (mirror is warn-only; a mirror failure must never fail the caller)
- Problem status after each mutation matches the expected facade mapping: `ignored` → `ignored`, revert → `created`, dismiss → absent, re-arm → `created`
- Problem `severity` unchanged from baseline after re-create (mapping `MapRepairSeverity` must not downgrade/upgrade)

## Validation

1. `GET /api/problems` and `GET /api/settings` match recorded baseline
2. `ha addons logs local_sambanas2 | tail -n 40` → no `ERROR`/`panic`/`FATAL`; at most `WARN` lines containing `Failed to sync repair` or `Failed to dismiss mirrored problem`
3. Addon still `started`, health 200

**Success criteria:** REST-only lifecycle transitions mirror 1:1 into `/api/problems` through the facade, all primary operations succeed, logs show no errors, baseline restored.
