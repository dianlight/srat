# Test Case: 007.009_alert-settings-api

## Test Objective

Verify the alert-settings backend contract: `alert_protected_mode`, `alert_addon_config_changed` and `alert_custom_component` round-trip through `GET`/`PUT /api/settings` (explicit `false` is serialized, never dropped), survive an addon restart, a problem `Upsert` never clears a stored ignore, and a disabled toggle suppresses emission at the source.

## Preparation

1. Ensure the SRAT addon is running: `ha addons info local_sambanas2` → `started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Record baseline settings (`alert_*` values) and problems (`GET /api/problems` keys) for later restore
3. Record current protection state (`ORIG_PROTECTED`) — this case forces protection ON temporarily and restores it

**If any preparation step fails** (addon not running, API unreachable), the test must be **skipped**.

## Execution

1. `GET /api/settings` → assert `alert_protected_mode`, `alert_addon_config_changed`, `alert_custom_component` are all present and `true` by default
2. `PUT /api/settings` with `alert_protected_mode: false` → assert 200 and the raw JSON body contains `"alert_protected_mode":false` (explicit false must serialize)
3. `GET /api/settings` → assert `alert_protected_mode: false` persisted
4. With protection mode ON and the toggle OFF: restart the addon, wait 12 s → assert `GET /api/problems` contains no `protected_mode` key (emission suppressed at source)
5. `PUT /api/settings` with `alert_protected_mode: true` → restart addon → assert `protected_mode` problem exists with `ignored: false`
6. Ignore persistence: `PUT /api/problems/protected_mode` with `{"ignored": true, "status": "ignored", ...}` (full problem body) → assert `ignored: true`; restart addon → assert still `ignored: true` (re-emit did not clear it)
7. Disabled-toggle suppression: `PUT /api/settings` with `alert_protected_mode: false` → assert `protected_mode` problem is gone without an explicit DELETE
8. Restore: toggle back ON, clear any ignore via problem DELETE (re-arm), restore `ORIG_PROTECTED` (restart if changed), restore baseline settings

**Assertions:**

- All three `alert_*` fields present, default `true`, explicit `false` round-trips and persists across restart
- Disabled toggle ⇒ no problem emitted after restart; re-enable ⇒ problem returns
- Stored ignore survives re-emission (re-emits never clear it)
- `PUT /api/settings` validation for unrelated fields is unaffected (spot-check hostname round-trip)

## Validation

1. Check addon logs: `ha addons logs local_sambanas2 | tail -n 30 | grep -iE "panic|FATAL"` → empty
2. Confirm settings and problems match the recorded baseline; protection state equals `ORIG_PROTECTED`
3. Confirm addon state `started` and health 200

**Success criteria:** Alert settings round-trip exactly, ignore is never cleared by re-emission, and the disabled toggle suppresses emission — with baseline fully restored.
