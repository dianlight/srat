# Test Case: 006.005_ws-reconnect-malformed-resilience

## Test Objective

Verify the live WebSocket endpoint (`ws://192.168.0.68:3000/ws`) stays resilient from a consumer perspective: frames keep flowing across an addon restart (reconnect works), every frame parses as `id:`/`event:`/`data:` with valid JSON payloads, and one malformed consumer-side frame never kills the stream — subsequent frames still arrive and listeners stay alive.

## Preparation

1. Ensure the SRAT addon is running: `ha apps info local_sambanas2` → `started`; health 200
2. Verify WS is reachable with a real WebSocket handshake **including an `Origin` header** (plain HTTP GET or `curl -N` without `Origin` returns `400 Bad Request` — the endpoint speaks RFC 6455 with SSE-style text payloads, not plain SSE). E.g. with `python3 docs/test/ws_listen.py` (stdlib: handshake + `Origin: http://localhost:3080`, decode text frames) → expect `101 Switching Protocols`, then `id:`/`event:`/`data:` frames
3. Open a logging WebSocket listener in the background: `python3 docs/test/ws_listen.py /tmp/srat_ws_res.log 300 & echo $! > /tmp/srat_ws_res.pid`; wait 10 s and confirm `hello`/`heartbeat` frames arrive

**If any preparation step fails** (WS unreachable), the test must be **skipped**.

## Execution

1. Frame-shape audit: capture 60 s of `/tmp/srat_ws_res.log`; assert every non-empty frame has an `event:` line and a `data:` line whose payload parses as JSON — record any malformed frame as evidence
2. Restart resilience: `ha apps restart local_sambanas2`, then open a FRESH connection and assert it gets `hello` with an advancing `id:` sequence within 30 s of the new boot. NOTE (proven 2026-09-24): a pre-restart connection never resumes on its own — the stream stalls with no close frame — so same-connection resumption must NOT be asserted; consumers must reconnect (this is exactly what the HA client's reconnect loop is for). Expect the restart itself to take minutes (graceful shutdown drains slowly; supervisor eventually force-kills the process).
3. Post-restart audit: capture 30 more seconds; assert frame shapes are still valid and `heartbeat` frames resume
4. Kill the listener: `kill $(cat /tmp/srat_ws_res.pid)`

**Assertions:**

- Zero unparseable frames in both capture windows (or each malformed frame logged as evidence with no stream stall after it)
- A FRESH connection gets `hello` with an advancing `id:` sequence within 30 s of the new boot (the pre-restart connection stalls with no close frame — consumers must reconnect; same-connection resumption is NOT asserted)
- No `panic`/`FATAL` in addon logs across the restart

## Validation

1. Confirm addon state `started` and health 200 after restart
2. Check addon logs: `ha apps logs local_sambanas2 | tail -n 30 | grep -iE "panic|FATAL"` → empty
3. `GET /api/problems` → reachable, 200; listener process reaped

**Success criteria:** Valid frame shapes throughout, stream self-heals across restart, logs clean.
