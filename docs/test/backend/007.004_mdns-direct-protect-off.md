# Test Case: 007.004_mdns-direct-protect-off

## Test Objective

Verify direct addon mDNS registration (`mdns_registration=true` + `use_component_mdns_proxy=false`, no custom component) broadcasts a correct `_smb._tcp` service while the addon runs with protection mode OFF, and that the broadcast resolves both from the HA host and from this Mac (local resolver), not only inside the remote environment.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `state: started`; `curl -s http://192.168.0.68:3000/api/health` → 200
2. Define base: `API_BASE_URL="http://192.168.0.68:3000"`
3. Confirm protection mode OFF: `ha addons info local_sambanas2 | grep -i protected` → `false` (or WS hello `protected_mode:false` via `ws://192.168.0.68:3000/ws`); if ON, toggle OFF via Supervisor UI (Addon → Protection mode) + restart, record deviation
4. Confirm no custom component in play: direct mode will set `use_component_mdns_proxy=false`; no `custom_components/srat` reload is performed in this case
5. Save baseline: `ORIG=$(curl -s ${API_BASE_URL}/api/settings)`; save to `/tmp/orig_mdns_off.json`; record `hostname`, `mdns_registration`, `use_component_mdns_proxy`
6. Compute expected instance name (NetBIOS sanitize: uppercase, truncate 15 chars, non-alphanumeric → `-`): e.g. `echo "$HOSTNAME" | tr '[:lower:]' '[:upper:]' | sed 's/[^A-Z0-9]/-/g' | cut -c1-15` → `$EXPECTED_INSTANCE`
7. Mac prerequisites: this Mac on same LAN/subnet as 192.168.0.68, `dns-sd` available (`which dns-sd`)

**If any preparation step fails** (addon not started, API unreachable, Mac not on same LAN), **skip**.

## Execution

1. **Enable direct mDNS:** `jq '.mdns_registration=true | .use_component_mdns_proxy=false' /tmp/orig_mdns_off.json | curl -X PUT ${API_BASE_URL}/api/settings -H "Content-Type: application/json" -d @- -w "%{http_code}\n"` → 200; `GET /api/settings | jq -r '.mdns_registration,.use_component_mdns_proxy'` → `true`, `false`
2. **Restart to apply:** `ha addons restart local_sambanas2` → wait 10s → `curl -s ${API_BASE_URL}/api/health` → 200
3. **Addon log assertion:** `ha addons logs local_sambanas2 | grep -a 'mdns'` → contains `registering direct mDNS` with `"instance":"$EXPECTED_INSTANCE"`, `"service":"_smb._tcp"`, `"port":445`; no `direct mDNS registration failed`
4. **HA-host browse (remote side):** `docker exec addon_local_sambanas2 sh -c "avahi-browse -a -t -p 2>/dev/null | grep -i '_smb._tcp' || avahi-browse -a -t 2>&1 | head -30"` → one `_smb._tcp` entry with `$EXPECTED_INSTANCE`; fallback `docker exec app_local_sambanas2 ...` if container name differs. Record raw output
5. **Mac browse (local side, MANDATORY):** on this Mac run `timeout 15 dns-sd -B _smb._tcp local.` → must list `$EXPECTED_INSTANCE._smb._tcp.local.` within 15s. Evidence: full output + timestamp
6. **Mac resolve (local side, MANDATORY):** `timeout 15 dns-sd -L "$EXPECTED_INSTANCE" _smb._tcp local.` → answers port `445`, TXT `path=/`, host resolves to `192.168.0.68` (or addon hostname `.local` → `dig +short <host>.local` contains 192.168.0.68). Record full output
7. **Detail cross-check:** service type exactly `_smb._tcp`, domain `local.`, port `445`, TXT contains `path=/`; instance equals NetBIOS sanitize of current `GET /api/settings | jq -r .hostname`

**Assertions:**

- PUT 200, GET reflects `true`/`false`
- Addon log shows direct registration with expected instance, no error
- Remote browse finds the instance
- Mac `dns-sd -B` finds the instance AND `dns-sd -L` resolves port 445 + host → 192.168.0.68
- Service details (type/domain/port/TXT/instance) all match spec

## Validation

1. Cleanup: restore `/tmp/orig_mdns_off.json` via PUT → 200 (or explicitly set `mdns_registration=false` if ORIG had it off); restart addon → wait 10s → health 200
2. Check logs: `ha addons logs local_sambanas2 | tail -30` → no `ERROR`/`panic`/`registration failed`; `ha core logs | tail -10` → no new traceback
3. Record evidence: PUT/GET payloads, log lines, avahi output, Mac `dns-sd -B`/`-L` full outputs with timestamps
4. Note deviations (e.g. container name `addon_` vs `app_`, protected toggle via UI, avahi missing → alternate tool used)

**Success criteria:** Direct broadcast correct on both sides with protect OFF; Mac browse + resolve both pass; cleanup restored; no log errors.
