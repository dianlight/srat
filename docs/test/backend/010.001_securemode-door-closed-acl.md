# Test Case: 010.001_securemode-door-closed-acl

## Test Objective

Verify that with `leave_front_door_open=false` the backend runs with `-addon` (SecureMode): the HA middleware allows trusted internal traffic (loopback via host socat + `homeassistant` fallback) and serves API normally, with no ERROR/FATAL/panic.

## Preparation

1. Addon running: `ha addons info local_sambanas2` → `state: started`
2. Define base: `API_BASE_URL="http://192.168.0.68:3000"`
3. Set door closed with full options (the options call REPLACES the whole object — always send all keys): `srat_update_channel=develop, auto_update=true, log_level=info, leave_front_door_open=false, disable_ipv6=true, clean_upgrade_dir=false, factory_reset=false, use_external_kernel_modules=true`; restart addon; wait ~40s
4. Confirm SecureMode: `docker exec app_local_sambanas2 ps -o args | grep srat-server` contains `-addon`; direct `curl` from LAN arrives as loopback (host socat `:3000 → 127.0.0.1:64289`), so a 401 from LAN is NOT observable — do not assert it
5. Confirm deployed binary matches working tree: `md5sum` installed vs upgrade-dir file equal, `telemetry configured ... version=<expected>` in addon log, middleware caller `server/ha_middleware.go:66`

**If any preparation step fails** (addon not started, `-addon` flag missing, binary mismatch), **skip**.

## Execution

1. **Direct health:** `curl -s ${API_BASE_URL}/api/health -o /dev/null -w '%{http_code}\n'` → 200 (loopback-trusted, expected — NOT an ACL bypass)
2. **Direct shares:** `curl -s ${API_BASE_URL}/api/shares -o /dev/null -w '%{http_code}\n'` → 200
3. **Middleware log assertion:** `docker logs app_local_sambanas2 | grep -a 'ha_middleware'` → contains `Trusted Home Assistant request missing X-Remote-User-Id header, defaulting to internal identity` with `"ip":"127.0.0.1"` for `/api/health` (proves branch middleware active, fallback identity applied)
4. **Caller-line check:** the log caller is `server/ha_middleware.go:66`; any other line (e.g. `:99`) means a stale binary — stop and redeploy before trusting results

**Assertions:**

- Health and shares return 200 via loopback trust
- Middleware warn lines present with `ip=127.0.0.1` and caller `:66`
- No `Unauthorized access from` lines for these requests

## Validation

1. Check logs: `docker logs app_local_sambanas2 | grep -a -c -E 'ERROR|FATAL|panic'` → 0 (excluding expected WARNs)
2. Record evidence: ps args line, middleware log lines, curl status codes
3. Leave addon in door-closed state for 010.002/010.003, or restore per suite plan

**Success criteria:** `-addon` active, loopback traffic served with fallback identity, caller line matches source, no log errors.
