# Test Case: 003.014_ha-managed-mount-detection

## Test Objective

Verify that SRAT detects Home-Assistant-managed mount points (paths under `/media/`, `/share/`, `/backup/`) and flags them `is_ha_mounted: true` in `GET /api/volumes`, while leaving SRAT-managed mounts (under `/mnt/`) not flagged. Read-only — no mutations.

## Preparation

1. Ensure the SRAT addon is running: `ha apps info local_sambanas2` → `started`; health 200
2. Confirm the host has at least one HA-managed mount (Supervisor): `ha mounts info --raw-json` → `mounts` non-empty with `user_path` under `/media/`, `/share/` or `/backup/`
3. Note the HA mount path (e.g. `HA_PATH=/media/...`) and any SRAT mount path (under `/mnt/...`) from `GET /api/volumes`

**If any preparation step fails** (addon not running, no HA mounts, no SRAT mounts to compare), the test must be **skipped**.

## Execution

1. `GET /api/volumes` → 200; for each partition, record `is_ha_mounted`
2. For every partition whose `mount_point` starts with `/media/`, `/share/` or `/backup/`: assert `is_ha_mounted == true`
3. For every partition whose `mount_point` starts with `/mnt/`: assert `is_ha_mounted == false`
4. `GET /api/shares` → 200; for shares whose mount point is HA-managed: assert `status.is_ha_mounted == true`
5. Check addon logs for the `IsHAManagedMountPath`/`SyncPartitionMountData` path (no ERROR)

**Assertions:**

- All HA-path mounts flagged true; all `/mnt/` mounts flagged false
- Share status mirrors mount status
- No ERROR in addon logs during the read

## Validation

1. Confirm addon state `started` and health 200
2. Confirm no mutations were issued (no POST/PUT/DELETE)

**Success criteria:** Detection flag agrees with path prefix for every volume and share; logs clean.
