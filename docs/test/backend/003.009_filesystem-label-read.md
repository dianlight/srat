# Test Case: 003.009_filesystem-label-read

## Test Objective

Verify read-only filesystem introspection and cross-endpoint consistency (cache-freshness angle from the remote-test skill §7a): `GET /filesystems`, `GET /filesystem/support`, and `GET /filesystem/label?partition_id=` agree with `GET /api/volumes` partition data. Strictly non-destructive — no format, no set-label, no mount/unmount.

## Preparation

1. Ensure the SRAT addon is running: `ha apps info local_sambanas2` → `started`; health 200
2. Pick a mounted ext4 partition from `GET /api/volumes` (e.g. `usb-General_USB_Flash_Disk_0111607137301461-0:0-part1` at `/mnt/usb_General_USB_Flash_Disk_0111607137301461_0_0_part1`) → note `PART_ID`, `VOL_NAME`, `VOL_FSTYPE`
3. If no mounted partition exists, the test must be **skipped**

**If any preparation step fails** (addon not running, no mounted partition), the test must be **skipped**.

## Execution

1. `GET /api/filesystems` → 200, non-empty list
2. `GET /api/filesystem/support?fstype=ext4` → 200; assert `ext4` reports full support (`canMount:true`, `canFormat:true`, `canCheck:true`, `canSetLabel:true`). NOTE: the endpoint requires the `fstype` query param — a bare `GET /api/filesystem/support` returns 400 `Filesystem type is required` (proven 2026-09-19).
3. `GET /api/filesystem/label?partition_id={PART_ID}` → 200; record `label`
4. Freshness assertion: the `label` from step 3 equals the partition `name` in `GET /api/volumes` for `PART_ID` (both read live state; any mismatch is a stale-cache bug — do NOT retry, file it per #1063)
5. Assert `fstype` for the partition matches between the label response and `/api/volumes`

**Assertions:**

- All three read endpoints return 200 with coherent data
- Label/name/fstype agree across `/filesystem/label` and `/api/volumes`
- No state was mutated (no POST/PUT/DELETE issued in this case)

## Validation

1. Check addon logs: `ha apps logs local_sambanas2 | tail -n 20 | grep -iE "panic|FATAL|ERROR"` → empty
2. Confirm addon state `started` and health 200

**Success criteria:** Read endpoints agree with the volumes tree; zero mutations; logs clean.
